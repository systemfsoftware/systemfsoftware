# Restore the Shared Vitest Config - Plan

## Goal Capsule

- **Objective:** `@systemfsoftware/vitest-config` (private, `packages/toolchain/vitest-config`) is back, and every package that consumed it before #689 consumes it again, with the config shape of `b1603415~1`.
- **Authority:** operator decision of 2026-10-09 reversing the per-package config ruling that #688/#689 implemented. Not re-litigated here.
- **Carry-forward:** every change main received after `4149b623` survives, in whichever file now owns the setting.
- **Invariant:** per-config `vitest list` output is byte-identical to `d204dfb2` (current main) in the default lane and under `VITEST_LANE=pr`.
- **Ships as:** one PR off `main`.

## Findings that change the brief's picture

- F1. #693 (`ffce5f4a`) edited no Vitest config: it touched only doc comments in `packages/runner/vitest/src` (`provided.ts`, `error.schema.ts`, `replay.schema.ts`). #692 (`5946b8b6`) touched no config either. The config carry-forward is #694 (`d8f2f5fb`) alone: 19 config files, `turbo.json` (`VITEST_LANE` dropped from `test.env`), four daemon `test` scripts (`--project conformance` dropped), `.github/AGENTS.md` (lane runbook line) and `.github/actions/checks-lane/action.yml` (no `VITEST_LANE=pr` export).
- F2. What #694 deleted lived in the shared config before #689: the PR lane (`isPrLane`, `laneLeavesOut`, `laneProjects`, `projectWithoutConformance`, `isConformanceProject`) and the conformance auto-split (`CONFORMANCE_GLOB`, `hasConformanceFiles`, `splitProjects`, `unitTest`, `unitInclude`, `conformanceTest`, `namedProject`, `withoutSpecs`). Carrying #694 forward therefore means deleting both from the restored `lib/base.js`, not just from the package configs.
- F3. Ten configs got their project name `unit` from the auto-split, not from their own file: `effect-atom/vitest.node.config.ts`, `effect-daemon-conformance`, `effect-daemon-spec`, `effect-cell-types`, `effect-memfs`, `effect-microsandbox`, `effect-readiness`, `rx-effect`, `trace-spec`, `storybook-gherkin/vitest.node.config.ts`. Main lists their tests as `[unit] …`. Without the split they would list unnamed. To keep the listing identical, each names its own test block `unit`; this is the one shape difference from `b1603415~1`, and it is #694's state, not a new choice.
- F4. Vitest 5's `vitest list` parses files statically by default and reports `No test suite found` for every file whose tests are registered at runtime (RuleTester, `makeFeature`, generated schema laws). Main fails that way on most packages. The evidence uses `vitest list --no-staticParse` (collects by running the files) plus `--filesOnly`.
- F5. `vitestFork()` was never published: npm's `@systemfsoftware/vitest@2.0.0` exports no `./plugin`, and its `minor` changeset (`.changeset/quiet-jeans-itch.md`) is still pending. After the restore nothing imports it, because `lib/base.js` provides the same context itself. Removing it changes nothing a consumer of a published version can see.

## Key Decisions

- KTD1. **Reverse both squashes, then re-apply #694.** Start from `git revert --no-commit 4149b623 b1603415` on `d204dfb2`. Every file neither #693 nor #694 touched lands at its `b1603415~1` content. Conflicted files are resolved by hand to `b1603415~1` plus the #693/#694 delta (table below). Not a plain revert: the brief rules that out, and F2 shows a plain revert would bring the PR lane back.
- KTD2. **Restored `lib/base.js` = `b1603415~1` minus the lane and the split (F2).** Everything else in it stays: guard resolution and exemption table, provided package name and workspace root, property tier, `AGENT`/`CI` tiers, timeouts, reporters, coverage, `effect/TestClock` alias, `sourceResolveConditions`, `isCI`. `defineConfig` adds guard and provide to the root when no projects are declared, else to each inline project.
- KTD3. **Remove `vitestFork()`** (F5): `src/plugin.ts`, its test and fixture, the tsdown entry and type map line, the `./plugin` export (regenerated by tsdown from `tsdown.config.ts`, REPO-S4), `PackageManifestFromJson`, the README section, and `.changeset/quiet-jeans-itch.md`. `defaults.ts`/`provided.ts` doc comments return to naming the shared config; #693's comment edits in `provided.ts` stay.
- KTD4. **Changesets.** `giant-jars-unite.md` (#689's `none` intent) and `quiet-jeans-itch.md` go with the revert; `property-failures-as-data.md` returns to its pre-#689 text. One new `pnpm change --bump none` intent names every publishable package whose build hash moves (devDependency edits, the fork's source).
- KTD5. **Keep `docs/plans/2026-10-09-0830-…`.** It is the record of the reversed decision; finished plans are history, as #689's R1 treated them. Doc edits #689 made elsewhere revert, except the `--only` cache learning in `turbo-cache-requires-complete-input-hash.md`, which is true without the plugin and is reworded to stop naming it.

## Units

- U4. Remove the plugin (KTD3); docs and changesets (KTD4, KTD5).
- U5. ## Tests

No test is added. The admission gate refuses each candidate: a test of the restored factory would pin a config the list diff already proves (characterization), and the plugin's own test file goes with the plugin. The evidence is scratch (U1/U5) and stays out of the tree.

## Assumptions this plan breaks if false

- A1. List identity covers selection. Broken if a config chose files from an env variable the capture does not vary. After the restore the only env reads are `AGENT`, `CI`, `STRYKER_MUTATOR_WORKER` and `COVERAGE` (tiers, reporters, timeouts, coverage), none of which picks files; the resolved-field capture varies the three tier variables.
- A2. Nothing outside the 42 configs imports the shared package. At `b1603415~1` the only other references are `turbo.json` inputs, two `effect-sim-kernel*` `turbo.json` inputs, the pnpm catalog, `gritlint.json`, the fork README and doctrine copies; all return with the revert.
- A3. Dropping the split cannot change which files run. The split only moved conformance files between two projects of one package; with one project the union is the same, which the list diff checks.
