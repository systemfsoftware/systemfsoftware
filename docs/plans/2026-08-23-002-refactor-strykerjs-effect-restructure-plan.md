## Product Contract

### Summary

The subsystem is 27,933 lines across 414 tracked source files and 8 published packages implementing mutation testing: a plugin contract, a Babel instrumenter, an orchestration engine, reporters, a CLI, a Vitest test runner, a TypeScript checker, and a package named `util`. The audit proves 25 SURVIVED violations of the repo's own law, and the shape of the failure is uniform: the subsystem is a class-and-container architecture wearing an Effect dependency. It has exactly **one** `Workflow.make` call, **zero** `Cell` phase chains and **zero** `Schema.TaggedError` declarations, against 168 typed-inject token uses, 182 `Promise<`-returning signatures, 113 `throw new` statements and 110 class declarations.

This change rewrites the subsystem's interior onto Effect and the sandwich, deletes `util`, inverts the reporter→engine dependency through a shared vocabulary on the contract, and removes 16 of 27 third-party dependencies by substituting Effect modules, platform builtins, and small owned implementations. No package is minted and no package survives unexamined: the nine capabilities currently conflated inside `mutation-run` become subpath exports rather than packages, because none has a binder the engine's own run does not control.

### Problem Frame

Three facts make this a rebuild rather than a repair.

First, the violation reproduces itself. `typed-inject` is not a local defect — it is the mechanism by which the object graph is assembled, and its types are on the published `.d.ts`, so every plugin an adopter writes inherits it. `Promise` on every protocol method is the same shape: the contract forces eager async on every implementation, which is why the engine had to hand-roll timeout and process-tree-kill machinery (`execa`, `tree-kill`, `npm-run-path`) that Effect's own `Scope` and `ChildProcess` already provide. Each new plugin, checker, or reporter written against the current contract adds another instance.

Second, the subsystem cannot measure itself. This subsystem _is_ the repo's mutation gate, and that gate keys its population on the `Workflow.make` boundary (`packages/testing/mutation/plugins/stryker-plugins/src/workflow-make-ignorer/MakeBoundaryIgnore.ts:273`). With one `Workflow.make` call in the whole subsystem, its own decisions sit where its own instrument cannot see them — a perfect score here would certify nothing.

Third, the law has no reach where the code is. The three oxlint plugins that make the idiom executable (`cell-vocabulary`, `effect-entrypoint`, `test-placement`) are registered by the `cli` package alone. `cli` is also the only package with any target-idiom adoption at all. That correlation is the diagnosis: the idiom exists exactly where a gate makes it exist, so a rewrite that lands without the gates will regress and every check will still exit 0.

The supply-chain concern the owner raised is measurable, not rhetorical. `weapon-regex` ships a 1.3 MB Scala.js artifact (`main.js`, 40,634 lines, plus a 1.3 MB source map) to serve **one** call site. `mutation-testing-metrics` and `mutation-testing-report-schema` are metric arithmetic and a data shape — both things this workspace can declare itself, and `Wire.mint` exists for exactly the second case. `typed-inject`, `rxjs`, `execa`, `npm-run-path` and `tree-kill` are all replaced by primitives already resolved in this lockfile.

## Planning Contract

### Key Technical Decisions

- KTD1. **Ports are capability-shaped, never callsite-shaped.** Replacing 168 typed-inject token uses invites one tag per injected member. That is refused: a per-operation projection has exactly one implementation by construction, so naming it a port inverts what a port is for, and its Live layer constructs the whole service anyway — privilege is relabelled, not reduced. The ports are therefore one per capability with a genuine second implementation: `TestRunner`, `Checker`, `Reporter`, `Ignorer`, `MutantInstrumenter`, plus the platform ports Effect already ships (`FileSystem`, `Path`, `ChildProcessSpawner`, `Clock`). No `*Deps` aggregator is exported (`REPO-A3`, and an exported projection forces every consumer to discover N aggregators where one port serves).
- KTD2. **Plugin composition is a pure fold over declared data.** A plugin declares what it contributes; it never mutates host state at registration. Concretely: a plugin module exports a `ReadonlyArray<PluginContribution>` — a tagged value naming its kind, its name, and the `Layer` that provides its port — and the engine folds the loaded arrays into one `Layer` with written-down merge and precedence rules (later contribution of the same kind and name wins, and the fold records the shadowing). This replaces `declareFactoryPlugin` + container registration. The composed configuration is inspectable as data without executing anything, which is what makes plugin order debuggable instead of emergent from import order.
- KTD3. **The protocol returns `Effect`, and that is what deletes three dependencies.** `Checker.check`, `TestRunner.dryRun`/`mutantRun`, `Reporter.*` return `Effect<A, TaggedError, R>`. Once the work is a value, `Effect.timeout` replaces the hand-rolled `ExpirableTask` race, `Effect.retry` replaces the retry loop, and fiber interruption reaching a `Scope`-bound `ChildProcess` handle replaces `tree-kill`. The current shape is why those existed: an already-started `Promise` cannot be held, retried, or interrupted, so the machinery had to live outside it.
- KTD4. **Process spawning moves to `effect/unstable/process`, and that is what deletes `tree-kill` — verified in the implementation, not the interface.** `repos/effect/packages/effect/src/unstable/process/ChildProcess.ts` exposes `make` (:603), `setCwd` (:792), `setEnv` (:831), `pipeTo` (:693), `KillOptions` (:242), the full POSIX `Signal` union (:177), and typed `StdinConfig`/`StdoutConfig`/`StderrConfig`/`AdditionalFdConfig` (:262, :294, :317, :340), with every command being an `Effect<ChildProcessHandle, PlatformError, ChildProcessSpawner | Scope>` (:42-46). The process-**tree** kill question was raised against this decision and is settled by reading the platform implementation rather than the handle's doc comment: `repos/effect/packages/platform/node-shared/src/NodeChildProcessSpawner.ts` kills the **group** first on every path — `killProcessGroup` issues `process.kill(-pid, signal)` on POSIX (:380) and `taskkill /pid <pid> /T /F` on Windows (:69-77), falling back to a single-process kill only if the group kill fails (:549-551) — and it does the same on interrupt (:502-507) and on non-zero exit (:516). `detached` defaults to `true` on non-Windows (`ChildProcess.ts:434`, applied at `internal/nodeChildProcessSpawner.ts:9`), which is what makes the group exist. `KillOptions.forceKillAfter` supplies the SIGTERM→SIGKILL escalation (:429-434). This is a strict superset of what `kill.ts:11` gets from `treeKill(pid, 'SIGKILL', cb)`, on both platforms, so no owned kill module is needed and none is written.
- KTD5. **Worker lifetime is a `Pool`; mutant fan-out is `Stream.mapEffect`. The two are separate, because conflating them destroys the recycling the current pool has.** This decision was rewritten after review: `Stream.mapEffect(mutants, run, { concurrency: N })` alone would acquire a test-runner per **mutant**, where `pool.ts:122-137` today creates `concurrencyTestRunners` workers once and re-queues each one after it finishes an item, amortising worker startup across thousands of mutants. Spawning a Node process and running a dry run per mutant is not a refactor of that, it is a different program with a different cost. The correct primitive is `Pool` (`repos/effect/packages/effect/src/Pool.ts`): `Pool.make({ acquire, size })` (:220) holds `size` scoped items, `Pool.get` (:423) yields one whose return-to-pool is the caller scope's finalizer, and `Pool.invalidate` (:511) retires a worker that crashed — which is exactly `pool.ts`'s recycle-or-replace behaviour, stated once instead of assembled from a `ReplaySubject`. `Stream.mapEffect` with a `concurrency` bound then supplies the fan-out over mutants, each step taking a worker from the `Pool`, and `Semaphore` supplies the cross-pool token accounting `concurrency-token-provider.ts` does today. `Fiber` interruption supplies cancellation, which is the correctness half of the change: today an interrupted Effect fiber does not interrupt an rxjs subscription, so two schedulers own the same processes and neither owns cancellation. `effect/unstable/workers` was considered and rejected for this use: it abstracts `Worker`/`WorkerRunner` message ports, while this pool needs full child-process control. Because this is the one unit where a plausible rewrite is _slower_ rather than wrong, U5 carries a wall-clock pin as an acceptance criterion, not just a behavioural one.
- KTD6. **The report shape becomes a `Wire` declaration, not a third-party type.** `mutation-testing-report-schema` is a data shape this workspace does not own, restated in members it does — precisely what `Wire.mint` exists for (`@systemfsoftware/effect-cell-types`, `Wire` namespace). Restating it buys the decode `mutation-testing-report-schema` never provided: today the report crosses process and file boundaries as an interface with no codec. `mutation-testing-metrics` is metric arithmetic over that shape and becomes a pure decision behind `Workflow.make`, which is also what puts it where the mutation gate can see it.
- KTD7. **`util` dissolves per-symbol to its single consumer, and four exported symbols die.** The map below is measured per symbol against every `.ts` file in `packages/`, `omp/`, `scripts/` and `agent-plugins/`, excluding `util/src/` itself, and it is the unit of work for U3 — not a summary of it. **Zero consumers, deleted:** `childProcessAsPromised`, `platform.caseSensitiveFs`, `escapeRegExpLiteral`, and the `DeepPartial` type in `deep-merge.ts`. **Exactly one consuming package, moved into it:** `isErrnoException`, `ERROR_CODES`, `findUnserializables`, `KnownKeys`, `Immutable`, `normalizeLineEndings`, `normalizeWhitespaces`, `requireResolve`, `resolveFromCwd` and `ExpirableTask` → `mutation-run`; `deepCloneNode` → `instrumenter`; `escapeRegExp` → `vitest-runner`; `strykerReportBugUrl` → `typescript-checker`. **Two consuming packages:** `deepMerge` (cli + mutation-run), `errorToString` (mutation-run + vitest-runner), `deepFreeze` (instrumenter + mutation-run), `propertyPath` (instrumenter + mutation-run), `normalizeFileName` (mutation-run + vitest-runner), `StrykerError` (cli + mutation-run), `testFilesProvided` (mutation-run + vitest-runner). **Three consuming packages:** `noopLogger` (cli + mutation-run + the `plugins/` tree), `notEmpty` (instrumenter + mutation-run + vitest-runner). Every symbol with two or more consumers lands on `plugin-api` beside the contract it serves, because that is the one package all of them already depend on and it is inward of all of them; a symbol with one consumer never lands there. `Task`/`ExpirableTask` are not moved but **deleted**: `Effect.timeout` is the replacement, so U5 removes the call sites rather than rehoming the module. `split` is excluded from this map — the identifier collides with `String.prototype.split` and a name-based sweep reports 74 false sites; its real import edges are resolved by U3 from the import statements alone.
- KTD8. **The engine's stage order becomes a phase chain, not a call sequence.** `run-stages/` currently asserts its order by the sequence of nested calls in `stryker.ts`. Rewritten as a `Cell` description — `Cell.read |> Cell.decode |> Cell.decide |> Cell.encode |> Cell.write`, interpreted once by `Cell.apply` — the order becomes a compile-time fact: each stage's return type carries the member the next stage's parameter demands, so an inversion omits a member and the compiler prints the sentence naming what must come first. A run whose real order writes before it can classify (instrument, then read coverage, then classify) is **one description carrying two layers**, opened by passing the prior `WriteDone` to `Cell.read` — not two descriptions composed by hand.
- KTD9. **This subsystem is the cell architecture's first production consumer, and that is a researched risk, not an accident.** Measured: `Cell.read`/`decode`/`decide`/`encode`/`write` appears 68 times in `packages/`, in exactly four files — the cell package's own type assertions and integration test, and the `cell-vocabulary` lint plugin's rule and its tests. No shipped package builds a production description today. `Workflow.make` is better proven, with production call sites in `packages/core/effect/daemon-spec/src/internal/RestartDecision.workflow.ts:79` and `packages/core/effect/cell/gen/src/DrawnDecision.workflow.ts:36`. The mitigation is ordering: `Workflow.make` decisions land first and independently (Phases B, E, F), and the phase chain is introduced in Phase D at exactly one site — the engine's stage order — where the ordering guarantee is the point. If `Cell.apply` proves unable to carry the engine's two-layer shape, the fallback is `Effect.gen` sequencing with the decisions still behind `Workflow.make`: the pure core is preserved and only the order's _enforcement_ degrades from compiler to review. That fallback is recorded here so it is a decision rather than a discovery.
- KTD10. **Logging keeps its transport and loses everything else.** Effect's `Logger` plus `Effect.log*` replace the six near-identical level methods, the level-priority map, the ANSI colourizer and the file appender (`Logger.layerFile`-shaped, or a `FileSystem`-backed sink). What it does **not** cover is the worker→parent TCP channel, which is a real capability: a forked child cannot write to the parent's stdout coherently, so the framed socket survives as a scoped `Layer` whose wire format stays the existing Effect `Schema` — the one already-correct thing in that subtree (`logging/logging-event.schema.ts`, validated on receipt at `logging-server.ts:32-34`). Stryker's `trace`/`fatal`/`off` levels have no Effect `LogLevel` equivalent and are mapped explicitly at the boundary, which is a decode, not a widening.
- KTD11. **Mutators decide over a repo-owned AST view, one decision each.** Every mutator today is typed over `@babel/core`'s `NodePath`, so no mutator can be a `Workflow.make` decision without dragging Babel into the pure core. The instrumenter therefore decodes a Babel node into a narrow owned view — node kind, operator, span, the few child references a mutator reads — and each mutator becomes `Workflow.make(MutationCandidate, decider)` over that view, dispatching with `Match.tag` + `Match.exhaustive`. This is what makes `conditional-expression-mutator`'s six-arm `if`/`else if` chain a closed exhaustive dispatch, and what makes adding an unhandled node kind a compile error rather than a silent absence of mutants. The registry becomes declared data (KTD2's shape), so adding a mutator is one file plus one array entry, and the array is inspectable.
- KTD12. **Substitutions are verified against this repo's Node floor before they are written, and two of them turn out to need no substitute at all.** Both manifests declare `"node": ">=20.0.0"`, so `Object.groupBy` (Node 21+) is **not** available: where grouping is genuinely needed (the checker's `group/` decision) it is Effect's `Array.groupBy` (`repos/effect/packages/effect/src/Array.ts:3055`), never the platform builtin. `lodash.groupby` itself is not migrated — a source sweep returns **zero import sites** for it in all eight `src/` trees against live entries at `mutation-run/package.json:124` and `:151`, so it is deleted outright, and the same sweep returns zero for `source-map` (`:131`). Two of the 27 declared third-party packages are therefore dead weight, which is a stronger result than substitution and is why R8 names them and R7 does not. Of the rest: `node:util.styleText` (Node ≥ 20.12, above the floor but below the CI runner's version — U14 pins the floor check) replaces `chalk` at its two call sites (`clear-text-reporter.ts:7`, `clear-text-score-table.ts:7`); `emoji-regex` has exactly one call site (`mutation-report/src/render-text.ts:2-4`) and is used to _count_ emoji for column width, so `Intl.Segmenter` with `granularity: 'grapheme'` is the same computation from the platform; `semver` has one load-bearing use — the engine-range check at `cli/src/main.ts:18` — replaced by an owned range check of roughly 30 lines, because pulling a range parser for one comparison is the exact shape Wlaschin's test rejects; `minimatch` has three consumers (`config/file-matcher.ts:4`, `config/options-validator.ts:9`, `project/project-reader.ts:15`) and is replaced by one owned matcher those three share; `diff-match-patch` is consumed only by `mutants/incremental-differ.ts:16`; `weapon-regex` only by `instrumenter/src/mutators/regex-mutator.ts:2`. Every one of those counts is from a `git grep` of the import specifier this session, so a substitution that turns out to have more consumers than stated is a plan defect the implementer reports rather than absorbs.
- KTD13. **Evaluator commits are separate by construction.** Each package's oxlint registration is its own commit (`CONST-E4`), landed immediately before that package's rewrite commit so the gate is observed red then green. - KTD14. **Verification is the contract lane that exists, and no new observer is built for this program.** `cli`'s `test:contract` packs the CLI as it would publish, installs it into a container, and drives the real binary over five fixture projects — the only altitude at which exit codes, real elapsed timeouts, spawned processes and shipped-artifact resolution are honest. A host-local golden-capture driver was built as a second observer and then deleted on the owner's ruling; the deletion is recorded in Key Decisions with the reason, because the failure mode it demonstrated is general: an observer that captures a system's output and then compares that system to its own capture fails on scheduling and passes on regressions. New authored tests are default-deny (`OP12`): property tests are added beside the new `Workflow.make` decisions where a universal holds (mutator idempotence, metric arithmetic, exit-code precedence, config merge associativity), composition tests cover the new `Layer` graphs, and nothing restates a constructor.
- KTD15. **A total map over a tagged union is the type's algebra, not a decision, and `plugin-api` may hold algebra but never a decision.** This was settled during U1 against a concrete case rather than in the abstract. `plugin-api/src/test-runner/RunResultHelpers.ts` holds `toMutantRunResult` and `determineHitLimitReached` — the audit's F20 site, and the reason the contract package has no `Workflow.make` despite deciding something. The leaf `AGENTS.md` says the package "decides nothing and must not be enrolled in mutation", which is how the decision stayed invisible. Three resolutions were considered. Moving both to `mutation-run` fails: `git grep` shows two independent consumers — `mutation-run/src/test-runner/command-test-runner.ts:87` and `vitest-runner/src/vitest-test-runner.ts:224-225` — and a plugin importing the engine inverts the dependency. Duplicating fails outright. Wrapping them in `Workflow.make` overreaches: once `reportAllKillers`' default is removed they take data and return data with no I/O, no clock and no policy input, which is the **algebra** of `DryRunResult` → `MutantRunResult`, not a decision over it. So: each function moves beside the type it maps (`determineHitLimitReached` into `DryRunResult.ts`, `toMutantRunResult` into `MutantRunResult.ts`), `RunResultHelpers.ts` is deleted with no forwarding export (`DEL1`), and the algebra carries LAW property tests and loses its mutation exemption — a `stryker.config.json` whose `mutate` glob names exactly those two files, and the leaf bullet rewritten to say so. The general rule this fixes in place: a `*.schema.ts` or a type module may export the total definitional functions of its own type, gated by property tests; anything that reads a clock, performs I/O, or takes a policy input is a decision and belongs behind `Workflow.make` in the package that owns the policy. `reportAllKillers` becoming a required parameter is what moves it across that line — a defaulted policy inside a mapping means no call site states the policy it wants, and changing the default silently changes every consumer's report.
- KTD16. **`Option` replaces `undefined` at every contract boundary this program touches.** Three separate members returned `T | undefined` where absence is meaningful: `determineHitLimitReached`, `Ignorer.shouldIgnore`, and the optional members of `Checker`/`TestRunner`/`Reporter`. Each forced the caller into a shape that cannot distinguish the cases — `timeOut ?? dryRunResult` at `vitest-test-runner.ts:225` reads identically whether the limit was not reached or the check was never run, and `typeof checker.group === 'function'` reads identically whether the checker has no grouping opinion or was written against an older contract. The optional members become total (an implementation with nothing to do returns `Effect.void`, and a checker with no grouping opinion returns the identity partition — which is exactly what the call sites synthesised, now stated once in one place instead of N times in the callers), and the meaningful absences become `Option`.

### Sequencing

Foundation-first, so every intermediate state is a coherent whole (demolition protocol).

`Phase A (U1, U2)` → `Phase B (U3)` → `Phase C (U4…U9)` → `Phase D (U10, U11)` → `Phase E (U12, U13)` → `Phase F (U14, U15)` → `Phase G (U16)`.

Phase A must precede everything that compiles against the contract, which is everything. Phase B must follow A because the shared `util` symbols land on the contract (KTD7). Phase C's units are internally ordered `U4 → U9` because the DI removal (U9) cannot complete until each subtree it wires has been rewritten. Phases D and E are independent of each other and of C's interior once A has landed, but both are sequenced after C so the engine's ports exist for them to implement against. Phase F is last before verification because reporters and the CLI consume everything.

One ordering hazard is called out because the phase list alone hides it: **U2 registers the `effect-entrypoint` and `cell-vocabulary` gates on all 8 packages, and 7 of those packages are not rewritten until Phases C–F.** A gate that fires on unrewritten code makes every intermediate commit red, which is the opposite of the demolition protocol's requirement that each intermediate state be coherent. U2 therefore lands each package's registration as the commit immediately preceding _that package's_ rewrite commit (KTD13), not all eight in Phase A: Phase A registers `plugin-api` only, and the remaining seven registrations are the first commit of the phase that rewrites their package. The R3 gate is consequently satisfied at the end of Phase F, not the end of Phase A, and any implementer who reads the phase list as "register all eight up front" will produce a tree that cannot compile between phases.

Each phase is a commit range on branch `strykerjs-subsystem`; each package's oxlint registration is its own commit immediately preceding that package's rewrite commit (KTD13).

## Loss ledger

Recorded before the work, so a stakeholder disagrees now rather than after:

- **Third-party plugin compatibility.** A plugin written against `@stryker-mutator/api` tokens or the current `typed-inject` contract will not load. Every package here is pre-1.0 ALPHA (`REPO-R1`) and the surface is already forked, so no migration is owed to an outside author — but the break is real and is the largest single loss.
- **The RegExp mutator's mutation catalogue.** Removing `weapon-regex` loses its Scala-derived regex mutation set. The plan reimplements over a narrower own token set; if parity against the contract lane's fixtures fails, the mutator is retired explicitly in a changeset rather than silently.
- **`Cell.apply` in production for the first time.** The phase chain has no shipped consumer today (KTD9). The fallback is `Effect.gen` sequencing with decisions still behind `Workflow.make`, which preserves the pure core and degrades only the order's enforcement from compiler to review.
- **Human-mode progress bar fidelity.** Replacing `progress` with an owned render will not reproduce its exact terminal output. Neither mode is byte-pinned: the contract lane asserts the machine-mode stream's shape, not its bytes, and human mode is not asserted at all.
