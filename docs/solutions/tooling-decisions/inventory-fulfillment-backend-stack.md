# Inventory Fulfillment Backend Stack - REPO-W8 Alternative Evaluations

REPO-W8 requires costly-to-reverse choices to evaluate at least two alternatives and record the
comparison under `docs/`. The plan unit U10 committed this record. Mechanism-level findings (peer
ranges, thenable contracts, spike protocol) live in
`effect-v4-unstable-stack-binding.md`; this record is the per-choice candidate matrix.

## Decision 1 - Persistence: drizzle-orm over raw @effect/sql

| Candidate                                            | Evidence                                                                                                                                                                                                                                                                                                                                       | Verdict                                |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `drizzle-orm@1.0.0-rc.4` (chosen)                    | Optional peer `effect >=4.0.0-beta.83`; ships `effect-postgres` and `effect-pglite` export trees with codecs, driver, session, migrator; typed table objects give the drizzle-backed port Layers (R8) compile-checked column references; migrations generated by `drizzle-kit` are plain SQL reviewable in the diff. The rc line is v4-native. | **Adopted** at exact pin `1.0.0-rc.4`. |
| Raw `@effect/sql-pg` / `@effect/sql-pglite` (no ORM) | Same rc.116 alignment, zero peer risk, but every query is hand-written SQL with hand-mapped rows - the store port implementation re-derives column names and row shapes for five tables plus better-auth tables, with no type tie to the schema definitions. Rejected as more surface for decode-never-cast violations, not less.              | **Rejected.**                          |
| Prisma                                               | No effect v4 integration: the client is promise-mode only, requires a generated engine binary, and has no migrator story an Effect layer can own. Binding it would re-create the thenable mismatch documented in the binding record, at greater depth.                                                                                         | **Rejected.**                          |

## Decision 2 - Transport: effect/unstable/rpc over the v3 line

| Candidate                                                 | Evidence                                                                                                                                                                                                                                                                                                                                                                 | Verdict                                                        |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `effect/unstable/rpc` on `@effect/platform-node` (chosen) | In-tree at the pinned `effect@4.0.0-rc.116` - `RpcGroup`, `RpcMiddleware`, `RpcServer.layerHttp`, `RpcClient` compose with the same Schema instances the domain exports; middleware composition gives R13/R15 enforcement at the wire boundary without a second auth layer. Unstable namespace costs are contained by the frozen-catalog contract in the binding record. | **Adopted** (in-tree, version rides the workspace effect pin). |
| npm `@effect/rpc@0.76.2`                                  | The v3 line: peers `effect ^3.22.1`. Importing it into an rc.116 workspace is the brand-name dependency capture the binding record names - two effect runtimes in one tree.                                                                                                                                                                                              | **Prohibited.**                                                |
| `effect/unstable/httpapi`                                 | Same in-tree stability story but no RPC client codegen, no typed error unions across the wire, no middleware channel - each consumer hand-rolls what `Rpc.make` states once.                                                                                                                                                                                             | **Rejected.**                                                  |

## Decision 3 - Auth: better-auth official drizzle adapter

| Candidate                                     | Evidence                                                                                                                                                                                                                                                                                                                                                                 | Verdict                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| better-auth official Drizzle adapter (chosen) | Official adapter, promise-mode, bound to its own drizzle view over the same raw client the Effect stack owns (spike-validated: signup + `getSession` roundtrip; cross-view visibility probe). Session cookies, link-account, and user tables arrive maintained upstream; the example hand-wraps only the promise boundary (`Effect.tryPromise` -> typed `Unauthorized`). | **Adopted** at exact latest-stable pin, spike-validated at install time. |
| Community effect wrappers around better-auth  | Unvetted single-maintainer bridges; none spike-validated against rc.116, each adding an unowned shim between two moving APIs.                                                                                                                                                                                                                                            | **Rejected** (unvetted supply chain).                                    |
| Hand-rolled cookie sessions                   | No link-account, no session-table lifecycle, no rotation - the example would demonstrate auth it wrote itself instead of the pack rules it exists to prove.                                                                                                                                                                                                              | **Rejected.**                                                            |

## Version Pinning and Bump Protocol

- Catalog entries are exact: `drizzle-orm@1.0.0-rc.4` (the `rc` dist-tag is the latest clean RC;
  `rc.5` is a canary build), `@effect/sql-pg` / `@effect/sql-pglite` at `4.0.0-rc.116`, better-auth
  latest stable at install time, validated by the U0 spike before the pin landed.
- The `unstable/*` namespace rides the workspace effect pin (`4.0.0-rc.116`). The example cannot
  bump it unilaterally; any effect-line change re-runs the four-leg spike before the catalog change
  lands.
