# Conventions platform: GritQL rules over the pinned grit engine

**Decision class:** tooling platform (REPO-W8 — costly-to-reverse: published package name, engine pin, gate wiring).
**Status:** accepted 2026-09-12.
**Maintenance owner:** this repo's platform surface; engine bumps are package releases through the changeset pipeline.

## Context

33 of 42 first-party package roots declared `references: [{ "path": "./tsconfig.node.json" }]`; 7 plain omissions, 2 doctrinally exempt. The correlation is perfect and nothing re-fires when dropped — an unchecked convention. The user ruled the remedy a **product**: a published, composable platform that extends far beyond tsconfig files, where anyone can plug their own GritQL rules in — GritQL-first, no proprietary rule format.

## The chosen shape

`@systemfsoftware/conventions` — a bin (`conventions scan`) over the exact-pinned `@getgrit/cli` `0.1.0-alpha.1743007075`. Rules are engine-native markdown/`.grit` pattern files; the wrapper selects files, composes a cwd-anchored `grit.yaml` (inline bodies; consumer rules namespaced `consumer_<name>`), spawns `grit check --json --no-cache`, and derives the verdict from `results[]`: **0 clean · 1 findings · 2 broken instrument** (missing engine, unreadable rule, empty roots selection — never green).

Engine facts this decision rests on (all spike-verified on the pinned engine):

- JSON and JSONC (comments) parse; absence rules compose from `$program` + `not contains`; object snippets are exact-shape, pair snippets match anywhere, `contains` is deep.
- `grit check --json` emits JSON on **stderr** and exits 0 even with findings; human mode exits 1 on violations — the wrapper parses JSON rather than trusting exit codes, and never relies on `--grit-dir` (silently ignored for pattern loading in this alpha; cwd-anchored discovery is the mechanism).
- Duplicate pattern names shadow silently — the wrapper namespaces and fails loud.
- The npm launcher's postinstall downloads the engine binary from GitHub releases: under this repo's deny-all policy the binary is absent and the launcher's self-repair (`grit install`) is itself broken against the current GitHub API. Delivery here is `nix/grit.nix` (pinned release archives, four platforms, `autoPatchelf`) through the devShell and CI — the dprint doctrine. Consumers either allow the postinstall or put the engine on PATH.
- Offline sandbox (`bwrap --unshare-net`, read-only tree, engine from the nix store): identical verdicts, no telemetry hang.

## Rug posture (pin = freeze, not break)

The rules are our data; the engine is a literal exact pin in `dependencies`. If the pin disappears from npm, installs freeze on the cached tarball; if the engine must move, the move is a package release through the changeset pipeline. **Replacement triggers** (fork the MIT engine — `getgrit/gritql`, stewarded under the biomejs org): the engine stops shipping glibc release binaries for current platforms; JSON parsing regresses under a re-pin; the pattern language takes a breaking change. At each trigger, verify the rule files still parse under the successor before shipping; the rules survive any engine that speaks GritQL.

## Biome postmortem (D1, inline)

biome 2.5.13 (latest at spike time) cannot compile `language json` GritQL plugins — the verbatim docs example fails; `language css;` compiles; bare snippets compile but target js; `biome search -l json` parses the node-form then errors ("Error executing the Grit query"; "Expected a definition"). Config discovery in worktrees needs `--config-path=.`; `biome.json` rejects `//` comments. Upstream refs: biomejs/biome#8723 (JSON GritQL, 2026-01), #2582, #7998, #6782. The lesson that generalized: biome's failure was its vendored plugin compiler, not GritQL — the grit engine itself natively targets JSON.
