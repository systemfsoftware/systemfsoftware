Add the `./runner` entry and the authoring API. `makeRunner(config, options)` returns the class a suite's `runner.ts` default-exports for Vitest's `test.runner`. It extends Vitest's `TestRunner`, so collection, retries and reporters stay Vitest's, and gives each try its own `TestSession` built from the composition root's `platform` and `engines` layers, `env`, config `defaults` and framework `version`; a test that never touches the app or the screen opens no engine. A config that does not decode fails every test with `ConfigInvalid` naming the key path before any engine is built, and `exitCodeReporter(setExitCode)` ends that run with exit code 2. A test whose `platforms` exclude its target's platform is skipped. Each runner instance writes its `report-1` partial under `<output>/partials/`, and `e2eTestFiles` holds the include and exclude globs a suite's `vitest.config.ts` uses. The package entry now exports `test`, `expect`, `describe`, `beforeAll`, `afterAll`, `beforeEach` and `afterEach`: `test(name, options?, body)` hands the body `app`, `agent`, `screen` and `platform` and maps `timeout`, `retries`, `tags`, `skip`, `only` and `platforms` onto Vitest. `expect(locator)` offers `toContainText`, `toHaveText`, `toHaveValue`, `toBeVisible`, `toBeHidden`, `toBeEnabled`, `toBeDisabled` and `toBeChecked`, which retry until the config's `assertionTimeout` or a per-call `timeout` and fail with the query, the expected value and the last value read; any other value gets Vitest's own assertion, and `expect.poll`, `expect.soft` and the asymmetric matchers are Vitest's.
