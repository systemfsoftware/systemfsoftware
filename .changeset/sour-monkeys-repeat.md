"@systemfsoftware/vitest": minor

Adds the `@systemfsoftware/vitest/kernel` subpath, the refusal kernel behind the `it` lanes, for a library that registers its own tests. The fork's refusals are a floor: `makeLedger` resolves a library's `tables` over the fork's own, so a library can reword a refusal or add one and cannot remove or narrow one (the weak value matchers, `.resolves`, `.rejects`, `expect.anything`, `expect.soft`, `expect.poll`, `toMatchObject({})` and `toThrow()` stay refused). A ledger admits one check per observed state, and is the only value `expectFor` and `drive` accept. A check is only built by `mint(judgement)` inside a `Subject`, and the judgement's `make` runs the same tables, the boolean refusal and the one-check rule; a judgement that calls no matcher is refused. `drive` takes an `Interpreter` whose steps open a new observed state only when they judged no check. `Gate`, `RequirementOf` and `BodyRefusal` take the library's texts, and `makeHandle` builds a non-Effect step whose requirement comes from the Effect it carries. `installGuard`, `markTask` and `isMarked` refuse a raw `expect` and an unregistered test.

The fork's own lanes keep their refusals and texts, with three run-time differences: a check wrapped in an Effect (`Effect.withSpan(check)`) no longer opens a new observed state, so a second one is refused as a second check; `expect(x).toString`, `valueOf` and any other member that is not a `to...` matcher is absent instead of minting a passing check; and the `expect` object's `anything`, `poll` and `soft` getters are non-configurable. `installGuard` now requires a refusal text, and a second call with a different text throws. `expect` and `Shapes` are type aliases now, because the `expect` type depends on the subjects a library passes.
