# @systemfsoftware/effect-spec-runtime@1.1.0

The published `effect` and `@effect/*` dependency ranges now start at 4.0.1 (`^4.0.1`, was `^4`), so a consumer resolves at least Effect 4.0.1. `@systemfsoftware/discern` also bundles `@effect/platform-node` and `@effect/platform-node-shared` 4.0.1 instead of 4.0.0. The Effect dependency now resolves to 4.0.5, and so does every `@effect/*` package installed with it.

- Effect 4.0.5 requires `effect@^4.0.5` as a peer, so a tree mixing 4.0.5 with an earlier 4.0.x fails at import, not at install. Install the versions your tree's `@effect/*` packages name.
- `FileSystem.File.Info` reports `dev`, `ino`, `rdev`, `nlink` and `blocks` as `bigint` where it reported `number`. Convert at your own boundary with `BigInt` or `Number`.
- A decision's `instructions` and its classify and probability `criteria` accept a JSON object or array as well as a string, and a rating's `criteria` are `{ label, description }` entries rather than bare labels. Read a level's `label`, not the entry. The lawful test runner is now a peer dependency under its own name, `@systemfsoftware/vitest`, instead of the `@effect/vitest` alias that pointed at it. Install `@systemfsoftware/vitest` and import `it`, `layer`, `expect`, and the rest from `@systemfsoftware/vitest`. `@systemfsoftware/effect-gherkin-spec` re-exports `it` and `layer` from `@systemfsoftware/vitest`. Published dependency ranges now name a full version: `vitest`, `@vitest/*` and `@types/node` ranges start at 5.0.1 and 26.6.2 (were `^5` and `^26`), `typescript` at 7.0.2 (was `^7`) and `playwright` at 1.63.0 (was `^1`). The `vitest` peer dependency of `@systemfsoftware/effect-gherkin-spec`, `@systemfsoftware/effect-schema-law`, `@systemfsoftware/effect-schema-vite`, `@systemfsoftware/effect-spec-runtime`, `@systemfsoftware/storybook-gherkin`, `@systemfsoftware/trace-spec`, `@systemfsoftware/vitest` and `@systemfsoftware/vitest-config` is now `^5.0.1`, so a consumer needs at least Vitest 5.0.1. `@systemfsoftware/trace-spec` depends on `@opentelemetry/semantic-conventions` `^1.43.0` (was `^1.33`). The packed `devDependencies` range on `@systemfsoftware/oxlint-config-recommended` moves to its new major. The file-end property judgement and the raw-`it` guard no longer run under Vitest's hook deadline. Both are synchronous, so the deadline could never stop them hanging; it only failed a file or a test with "Hook timed out in 10000ms" when a busy host stalled the worker, while every test passed. An explored case runs its seeded schedules only when its baseline had a choice point, so a choice-free case runs once. Its leak-check second run, on a fresh build, now runs the case once more with no seeded schedules (KernelCase.exploreOnce: the decision path CONFORMANCE_REPLAY names, else the baseline) instead of repeating every seed. A passing case costs 2 kernel runs without a choice point and 252 with one at per-change, where both cost 502 before. State the first run leaves behind still fails the second run as LeakedState; a choice-free case that leaks now reports LeakedState rather than a seed. Internal build-cache keys only: the build task now hashes a package's `lib/` sources; nothing a consumer installs changes. Build input only: the workspace @systemfsoftware/vitest test runner these packages build against changed; nothing a consumer of these packages sees changed. Test configuration only: package tests load the shared Vitest config again. No published code or types change. Internal: mutation configuration and its Stryker devDependencies only; no published file changes. A check whose matcher returns a promise — `toMatchScreenshot`, or an async matcher registered with `expect.extend` — now holds its step until the promise settles. A rejection fails the test that yielded the check, carrying the line that wrote it, instead of passing that test and surfacing later as an unhandled error. A written check that is never yielded is still refused. The matcher may build chai assertions after it awaits: the raw-`expect` guard's window stays open until its promise settles. That window is global to the worker, so a raw `expect` from a concurrently running test is let through while it is open, and refused again once it closes. A suite's shared layer (`Suite.openShared`, `Suite.openSharedCase`, and so `.withLayer` on a feature) is now built once, by the suite's first case, shared by every case in the suite, and released when the suite ends. It used to be rebuilt fresh around every case, so an expensive fixture such as a server or a database was started and stopped once per scenario. A test that needs state no other case sees moves that state into the case layer (`Suite.openCase`, `.withScenarioLayer`). No consumer-visible change; the published API is unchanged. Update peer and runtime dependency on `effect` and companion packages to `4.0.0-rc.117`. Seeded schedules place their priority change points among the case's explored decisions instead of across every step including the layer build, so a change point no longer falls where no choice is made. A two-fiber lost update behind a layer build was found by 70 of 1,000 seeds instead of 32. A saved CONFORMANCE_REPLAY value with a decision path still reproduces; a seed-only value replays a different schedule. Kernel runs are serialized. A run started while another is live now waits behind it, in arrival order, instead of failing: two runs never interleave, so a scenario never sees another run's decisions, and a suite whose cases drive the kernel can run its tests concurrently.

`@systemfsoftware/vitest` adds `captureRunBinding`, the running test's run binding. `bind(effect)` re-provides it to an effect a library runs on a runtime of its own — its own scheduler, a worker, a simulation kernel — so the checks inside it count as that test's assertions, report softly, and see the same `owned` regions.

`@systemfsoftware/effect-spec-runtime` runs a case that declares no live reason through that runner, and a case's annotations now reach the test's report. Build input only: the workspace @systemfsoftware/vitest test runner these packages build against changed; nothing a consumer of these packages sees changed.
