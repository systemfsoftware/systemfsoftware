# @systemfsoftware/effect-e2e@1.1.0

Add the replay cache's pure core: the cache key context and its SHA-256 digest, unique() slot templating, the trace-1 entry, the replay decision, and the end-of-attempt recording settlement. Nothing new is exported from the package entry; the package now depends on @noble/hashes. Add the `./report` entry. `buildReport` turns a worker's attempt log into a `report-1` document: one result per test, target and agent with every attempt in order, the run status and exit code folded from each final attempt, and a summary counted from the results. `mergeReports` merges the partial reports of one run into one report that is the same in any order, and refuses partials of different runs or with a result in common. `decodeReport` and `report1JsonSchema` read and describe the document. The `list`, `json`, `junit` and `markdown` reporters render it with matching counts; `emitReports` writes `junit.xml` and `summary.md` under the output directory and returns the terminal text for `list` and `json`. `TestSession.layer` now also needs an `ArtifactStore` (`FileArtifactStore` or `MemoryArtifactStore` from `./run`): a try the `trace` setting admits (by default, any non-passing try) leaves `trace.md`, a masked `screen.png` and a redacted `screen.txt` under `<output>/results/<title slug>-<8 hex digits>/`, read within 5 seconds before the engine closes and listed in the result's `artifacts` and `tracePath`; a refused evidence write is recorded on the attempt as `ARTIFACT_WRITE_FAILED`. Assert and wait-for steps now carry their cache lookup and write, model calls and tokens, and extract steps carry model calls, tokens and the lookup `Off`. `exitCodeOf` maps a `RunEnding`, a judged verdict or a refused config (exit 2), to its exit code. `Attempt` moved from `.` to `./report`. These breaking changes ship as a minor bump because the package is pre-1.0 and has not been published to npm. The `@systemfsoftware/effect-e2e/engine` entry now exports `EnvironmentUnavailable` (`ENVIRONMENT_UNAVAILABLE`), so an engine adapter whose browser or device cannot start fails its layer with the typed environment failure. Add the deterministic run verdict fold, the default failure-cause table and the exit-code projection. They are internal: nothing new is exported and the packed package is unchanged. Add `makeGlobalSetup(config, options)` to `./runner`, the Vitest global setup a suite registers beside its runner. Before any worker starts it removes the previous run's report partials and merged report and hands every worker one run id; at teardown it merges the workers' partials into one run report holding each result once. Each runner instance now names its own partial and rewrites it after every finished test, so a worker that dies leaves its completed results behind and the merged report ends with run status `error`. A runner without the global setup still runs and stamps its own run id. Add the `./agent` entry: `act` drives an agent toward a natural-language goal. It replays a recorded flow first and hands off to the model when a recorded control changed, then asks the model for one action at a time within `maxSteps`, `maxModelCalls` and `timeout` (`STEP_BUDGET_EXHAUSTED`, `STEP_TIMEOUT`). It returns an `ActResult` with the summary, cache decision, model-call count and committed actions, and reports each action to `onAction` with source `model` or `replay`. `SecretLedger` fills a `Secret` param by name, keeps its value out of every model request, log, trace and recording, and refuses a screenshot after a secret fill with `POLICY_DENIED`. Add the check, failure, step-record, run-verdict and report-1 schemas and the report-1 JSON Schema generator. They are internal: nothing new is exported and the packed package is unchanged. Add the `./run` entry: the per-try run engine. `TestSession.layer(input)` builds one try of one test from its config, target, agent, a fresh secret ledger and an engine source, and needs only `ModelGateway` and `CacheStore`. Its `open`, `act`, `assert`, `waitFor` and `extract` each start a step and return a handle whose `join` awaits it. The engine opens on first use, at most once per try, so a test that never touches the app or the screen opens no browser. `endAttempt(ending)` is uninterruptible: it interrupts steps still running, closes the engine if it was opened, settles and writes the replay cache, and appends the attempt to an `AttemptLog`. A step that was never joined, or was still running when the test returned, fails the try `STEP_NOT_AWAITED`. A cache write that fails marks that step `not-written` and never changes the status. `admitTest` skips a test whose `platforms` do not include the target's platform, recording a skipped attempt with the reason, and the log's `verdict` decides the run from each test's final attempt, so a test that passes on retry passes the run. In `report-1`, an attempt is now `Ran { id, retry, status, steps, errors }` or `Skipped { id, retry, reason }`; no report-1 producer has shipped, so no stored report changes. The root entry exports the `Attempt`, `RunVerdict` and `TestPlatform` types. Add the `@systemfsoftware/effect-e2e/model` entry: the `ModelGateway` service, the provider-neutral `ModelRequest`/`ModelResponse` vocabulary, and `OpenAiCompatible.layer({ model, apiKey })`, which calls OpenRouter or any OpenAI-compatible `/chat/completions` endpoint over an `HttpClient` the caller provides. Provider replies fail only as `MODEL_PROVIDER_FAILED`, `MODEL_REFUSED`, `MODEL_OUTPUT_INVALID` or `CONTEXT_OVERFLOW`, and the API key is sent only in the `Authorization` header. The model config gains an optional `maxInputTokens` budget; a request estimated over it fails as `CONTEXT_OVERFLOW` before anything is sent. A test's `skip` option now takes a reason string. The report records the reason on the skipped result, and Vitest prints it as the skip note. Add `assert`, `waitFor` and `extract` to the `./agent` entry. `assert` and `waitFor` have the model resolve a sentence into a closed check once, with one repair, and decide it with a pure three-valued evaluation: holds passes, does not hold fails `ASSERTION_FAILED`, and a fresh check the screen cannot support ends `ASSERTION_INCONCLUSIVE`. No model answer is a verdict. A check that held is staged for the cache and replays with zero model calls; a stale recorded check is re-resolved with one call. `waitFor` polls every `interval` (3 s) until `timeout` (30 s), and on timeout its last evaluation decides the code. `extract` takes a schema that is both Standard Schema and Standard JSON Schema, validates the model's value with one repair, and fails `MODEL_OUTPUT_INVALID` on a second invalid answer. `vision: true` adds a masked screenshot and `'only'` sends the screenshot without the tree; a model or engine that cannot serve the mode fails `UNSUPPORTED_CAPABILITY` before any model call. A failed assertion records a model-proposed cause with cited evidence, which never changes its code, cause or the run status. Model specs gain `vision` (default `false`). Cache keys gain `step: 'act' | 'judgment'`, so every recorded cache entry from an earlier version misses once and is re-recorded, and a passing assertion confirms its own recording. New `@systemfsoftware/effect-e2e/cache` entry: the `CacheStore` service that persists replay recordings, and two stores for it. `CacheStore` exposes `writable`, `read(digest)`, `write(digest, entry)` and `delete(digest)`. A read never fails: it answers `Hit` with the decoded `trace-1` entry, `Miss`, or `Invalid` with a reason (`unreadable`, `oversized` or `not-trace-1`), which a run treats as a miss. A write answers `Written`, `ReadOnly` or `Oversized` (entries over 1 MiB are never stored), a delete answers `Deleted` or `ReadOnly`, and only a storage failure is `CacheStorageFailed`. `FileCacheStore.layer({ directory, mode })` requires `FileSystem` and `Path` and keeps one `<digest>.json` file per entry with mode 0600, replaced atomically through a temporary file and a rename. `MemoryCacheStore.layer({ mode, seed })` is an in-memory store that answers every operation the same way. Both open as `read-only` or `read-write`; a read-only store never writes or deletes. New `@systemfsoftware/effect-e2e/engine` entry: the engine contract an engine adapter implements. `Engine` is the service tag; its shape opens a page, observes the semantic tree, queries, acts, reads, takes screenshots, reports the route, logs and capabilities, and closes. Each operation fails only with the engine failures `LOCATOR_NOT_FOUND`, `LOCATOR_AMBIGUOUS`, `ACTION_FAILED`, `AUTOMATION_UNSUPPORTED`, `APP_UNREACHABLE`, `APP_NOT_OPEN` and `ARTIFACT_WRITE_FAILED`, exported from the same entry with the observation, action, locator, capability, read, log and screenshot schemas. `Engine.layerTest(site)` provides an in-memory engine over a `MemorySite` for tests. The entry imports no browser driver and no Node module. New package. `@systemfsoftware/effect-e2e` publishes the suite config edge: `defineConfig` and `web(...)` build an `e2e.config.ts` as plain data, the `unique`, `secrets` and `credentials` helpers name values the run resolves later, and `decodeConfig(value, defaults)` decodes it once into an `E2EConfig` with every default filled, or fails with `ConfigInvalid` naming the key path that broke. Importing the package performs no effects. Add the engine schemas for observations, actions, locators, routes and capabilities. They are internal: nothing new is exported and the packed package is unchanged. Add tracing and metrics. `./run` exports `Telemetry`, a silent-by-default sink every `act`, `assert`, `waitFor` and `extract` step reads, and `OtlpTelemetry.layerFromEnv`, which exports OTLP/JSON spans and counters over the `HttpClient` you provide only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; with no endpoint nothing is sent. Steps emit `e2e.act`, `e2e.assert`, `e2e.waitFor`, `e2e.extract`, `e2e.replay`, `e2e.engine.action` and `e2e.model.call` spans (the last with `gen_ai.*` attributes), and the `e2e.replay.outcomes`, `e2e.model.calls` and `e2e.model.tokens` counters, counted from the same step records the report folds. The report summary gains `hitRate` (replayed over replayed, handed off and missed; 0 when no step was cache-eligible), and the `list` reporter prints the cache split with it. Add the `./runner` entry for running suites under Vitest. `makeRunner(config, options)` returns a runner class extending Vitest's `TestRunner`: each try gets its own session, a test that never touches the app opens no engine, a test that passes on retry passes, and a test whose `platforms` exclude its target is skipped. A config that does not decode fails every test with `ConfigInvalid`, and `exitCodeReporter` ends that run with exit code 2. The entry also exports `e2eTestFiles`, `test`, `expect`, `describe` and the hooks. `test` hands the body `app`, `agent`, `screen` and `platform`; `expect(locator)` matchers retry until `assertionTimeout` and fail with the last value read, and other values use Vitest's `expect`. `vitest` is a peer dependency; no other entry imports it.
