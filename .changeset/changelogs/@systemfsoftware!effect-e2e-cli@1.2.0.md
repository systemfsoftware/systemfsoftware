# @systemfsoftware/effect-e2e-cli@1.2.0

A suite scaffolded by `effect-e2e init` now runs with its config's `retries` and `workers`, or with the CI run shape (one retry, one worker) when neither is written. `effect-e2e run --retries` and `--workers` override the config for that run. A suite scaffolded before this release ignores both keys until you update its Vitest config: import `e2eRunShape` from `@systemfsoftware/effect-e2e/runner` and the `options` the suite's runner module exports, then add `...e2eRunShape(config, options),` to the `test` block. `effect-e2e run --ai-trace` writes `ai-trace.json`, the masked model calls, into each failed test's result directory, whatever `--trace` says. Without the flag the suite's own `aiTrace` setting applies. The README now covers installing the `effect-e2e` bin from the systemfsoftware flake tarball as a devDependency on Node 24 or later. The executable is unchanged. Add `effect-e2e run`. It runs an effect-e2e suite under Vitest in the same process, prints the run's merged report with `--reporter list|json|junit|markdown` (default `list`), and exits with the report's code: 0 passed, 1 failed, 3 blocked, 4 error, 130 interrupted. A refused config, a missing suite root, conflicting flags, a suite without the effect-e2e global setup, or a run that writes no report exits 2; a refused config never reads an older report. Flags: `--dir`, `--target`, `--agent`, `--tag`, `--no-cache`, `--strict-cache`, `--workers` (Vitest maxWorkers), `--retries`, `--timeout`, `--output`, `--trace`, `--last-failed` (reads the previous report where this run writes), and test file filters. Suites `init` generates now set `testTimeout` from the config's `timeout` (default 120 s) instead of Vitest's 5 s.
