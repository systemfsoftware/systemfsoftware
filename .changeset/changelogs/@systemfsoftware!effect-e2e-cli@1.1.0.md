# @systemfsoftware/effect-e2e-cli@1.1.0

New package. `@systemfsoftware/effect-e2e-cli` ships the `effect-e2e` bin. `effect-e2e init --dir <suite>` scaffolds a runnable effect-e2e suite: `e2e.config.ts` (the only generated file that reads `process.env`, and the source of `BASE_URL` for the test workers), `vitest.config.ts`, `runner.ts`, `global-setup.ts`, a deterministic `tests/example.e2e.ts`, an agent `tests/example-agent.e2e.ts` that is skipped with a reason naming the gateway's API key variable when that variable is unset, a `test:e2e` script and a `.e2e/` ignore entry. `--engine` (`web`) and `--gateway` (`openrouter`, `openai-compatible`) are prompted for when absent; `--model` defaults to the gateway's default model. `init` exits 2 and writes nothing when a file it would write already exists; `--force` replaces those files and keeps the suite's own `package.json` scripts and dependency ranges. Dependencies are installed with the package manager whose lockfile is nearest the suite unless `--no-install` is given. The package exports only `./package.json`.
