"@systemfsoftware/alchemy-stack-layer": minor

New package. `alchemyStack(name, config)` returns a service tag, distinct for each stack name, whose service is the stack's outputs, with a `layer` that deploys the stack on `@alchemy.run/test`'s engine when acquired and destroys it when released. `config.deploy` takes a stack definition, or a function that receives `deploy` and returns the outputs, with an optional `setup` layer for what that function needs; stacks are destroyed in reverse deploy order, and each is registered for destroy before its deploy starts. Dev mode, sidecar and stage resolve as `@alchemy.run/test` resolves them; `dev`, `stage`, `sidecar` and `profile` are forwarded unchanged. Without a configured `stage`, the stage gets `_` and 8 hex digits of the SHA-256 of the test file's repository-relative path. Before deploying, the layer destroys any deployment left at the stage; if that fails, acquiring fails with `StackDestroyFailed` and nothing new is deployed. A cloud deploy over local or in-memory state fails with `DurableStateRequired` before it deploys; a failed deploy fails with `StackDeployFailed` and a failed destroy with `StackDestroyFailed`, each naming the stack and the stage; a stack with no configured stage built outside a running test file fails with `StageUnresolved`. `alchemy`, `@effect/platform-node` and `effect` are peer dependencies.
