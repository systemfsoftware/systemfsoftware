# Evidence Graph

`@ttsc/evidence` turns a specification into a compile error until some declaration cites it by name.

You declare the graph in `lint.config.ts`: which files owe answers, and which documents, schema models, API operations, or TypeScript symbols they owe answers to. Every pair is one independently complete obligation. A unit nothing acknowledges fails the build, in the same diagnostic stream as a type error.

```tsx
/**
 * @evidence docs/discount.md#coupon-stacking
 *           States the per-issuer stacking limit this section defines.
 */
export function CouponStackingNotice(props: IProps): JSX.Element;
```

`@evidence <target> <reason>` names one unit of the spec and why this declaration answers for it. Without it the next build stops:

```text
$ npx ttsc
error TS16411: [evidence/graph] Missing acknowledgement for 'docs/discount.md#coupon-stacking'
  (Markdown H2 'Coupon Stacking' at docs/discount.md:3)
  in Claim 1 reference 1 (markdown, symbols: h2, h3).

  Cite the artifact that answers for this unit with @evidence on a selected
  typescript host, building that artifact first when none does, or write
  @evidenceExclude on an eligible carrier when nothing here owes it. Never
  leave an untrue tag standing just to pass this check; it removes the error,
  not the problem.
```

You do not write these tags. An AI coding agent has to clear the errors to finish, and the error list is the task list.

A type error is caught by the compiler and wrong behavior by a test; an omission has only ever been caught by a person rereading everything until a round finds nothing new, the loop until dry. Coverage needs a denominator, and the graph hands it to the compiler. Documents gain the reference integrity code always had.

100% coverage is still not 100% truth, so human review narrows to one question: whether each written reason is true. `@evidenceReview` records the verdict with a fingerprint that expires when the cited content changes. The compiler handles omissions. Humans handle falsehoods.

One coding engine built the same four applications twice from the same frozen requirements, with and without the graph: coverage of 51.6–85.5% against 100%, on between a thirteenth and a fifth of the tokens, with review's share falling from 90–95% to 15–41%. [The benchmark](/docs/benchmark/evidence) has the thirteen edges behind each score, what both arms spent, and the method.

What that buys is the handoff. Whether a human or an AI wrote the requirements, a human reviews them last, and the agent builds everything below that reviewed layer at 100% coverage: [Examples](/docs/evidence/examples) shows the shape, and [Adoption](/docs/evidence/adoption) shows the path.

## Install

`@ttsc/evidence` is a rule contributor to [`@ttsc/lint`](/docs/lint), not a top-level `ttsc` plugin. The compiler never loads it; `lint.config.ts` does, and violations surface in every `ttsc` build, every `--noEmit` check, every `ttsx` run, and in the editor through `ttscserver`, with no CI job to add.

```bash
npm install -D ttsc @ttsc/lint @ttsc/evidence typescript
```
