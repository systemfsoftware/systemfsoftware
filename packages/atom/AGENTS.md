# AGENTS.md — `@systemfsoftware/effect-atom` + `@systemfsoftware/effect-atom-react`

Root `AGENTS.md` governs; this leaf carries only the delta.

## Rules

| ID      | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Gate                                                                                                                                                                |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AT1** | Each package ships one entry (`mod`) whose only export is one namespace barrel (`Atom`, `AtomReact`), built by tsdown with two type gates (`build` = `tsdown && pnpm dts:check && pnpm api:check`) and one api-extractor report (`etc/<package>.api.md`, report-only, `dtsRollup.enabled: false`). Add a module by exporting it from the barrel, never as a new package subpath.                                                                                       | `pnpm --filter @systemfsoftware/effect-atom build` + `dts:check` + `api:check` exit 0                                                                               |
| **AT2** | `dts:check` (`tsc --noEmit -p tsconfig.dts.json`, `skipLibCheck: false`, `types: ["node"]`) is the gate that reads the shipped dts; api:check audits the API report only (no rollup). Keep both green — a dependency shipping a broken dts turns dts:check red, and that is the point.                                                                                                                                                                                 | `pnpm --filter @systemfsoftware/effect-atom dts:check`                                                                                                              |
| **AT3** | Import type-only members directly (`import { getResult, type Registry } from './Registry'`), never through a namespace import — oxlint's `import/namespace` resolves the runtime `.mjs`, where type-only exports do not exist. Never silence the rule in `oxlint.config.ts`.                                                                                                                                                                                           | `pnpm --filter @systemfsoftware/effect-atom lint`                                                                                                                   |
| **AT4** | Only the propagation state machine (`effect-atom/src/atom-node.ts`) is mutated. Adding `registry-engine.ts` made the CI job exceed its 30-minute per-package limit with no report. `stryker.config.ts` runs the node-only `vitest.node.config.ts`, because CI's Mutation job installs no browser. `src/internal/node-lifetime.ts` never enters a `mutate` glob; it observes process lifetime, so a surviving mutant proves nothing. The React package is not enrolled. | `git ls-files 'packages/atom/effect-atom-react/stryker.config.*'` prints nothing and `grep -c node-lifetime packages/atom/effect-atom/stryker.config.ts` prints `0` |
| **AT5** | `~effect-atom/atom/…` TypeId literals are wire format, not module paths — `Hydration` payloads are keyed on those strings; renaming the packages must not change them.                                                                                                                                                                                                                                                                                                 | `review`                                                                                                                                                            |
| **AT6** | Browser coverage lives in each package's `browser` Vitest project (playwright provider, headless chromium) — never jsdom, never jest-dom; node tests stay in the `node` project, which excludes `tests/browser/**`. The environment needs `pnpm exec playwright install chromium` before either package's `test`.                                                                                                                                                      | `pnpm --filter @systemfsoftware/effect-atom test` and `pnpm --filter @systemfsoftware/effect-atom-react test`                                                       |
| **AT7** | `atom-react` keeps `"jsx": "react-jsx"` in every project that holds `.tsx`-capable sources — `tsconfig.app.json` and `tsconfig.test.json` — Vite derives its esbuild JSX mode from tsconfig; without it every JSX test site fails with `React is not defined`.                                                                                                                                                                                                         | `pnpm --filter @systemfsoftware/effect-atom-react test`                                                                                                             |
| **AT8** | Every tracked TypeScript file belongs to exactly one project behind the reference-only `tsconfig.json`: `tsconfig.app.json` (src/), `tsconfig.test.json` (tests/), `tsconfig.node.json` (root tooling configs); `typecheck` runs `tsc -b`, so tsc compiles the tests, not just Vitest.                                                                                                                                                                                 | `pnpm --filter @systemfsoftware/effect-atom typecheck && pnpm --filter @systemfsoftware/effect-atom-react typecheck`                                                |

## Verification

```bash
pnpm --filter @systemfsoftware/effect-atom build && pnpm --filter @systemfsoftware/effect-atom-react build
pnpm --filter @systemfsoftware/effect-atom typecheck && pnpm --filter @systemfsoftware/effect-atom lint && pnpm --filter @systemfsoftware/effect-atom lint:tsgo && pnpm --filter @systemfsoftware/effect-atom test && pnpm --filter @systemfsoftware/effect-atom test:types && pnpm --filter @systemfsoftware/effect-atom attw
pnpm --filter @systemfsoftware/effect-atom-react typecheck && pnpm --filter @systemfsoftware/effect-atom-react lint && pnpm --filter @systemfsoftware/effect-atom-react lint:tsgo && pnpm --filter @systemfsoftware/effect-atom-react test && pnpm --filter @systemfsoftware/effect-atom-react test:types && pnpm --filter @systemfsoftware/effect-atom-react attw
pnpm exec playwright install chromium
```

The chromium install enables the `browser` (headless chromium) Vitest project in both core and react `test` runs; the `node` project excludes `tests/browser/**`.

## Inapplicable pack rules

Neither package authors an outside interaction as a Cell, so six `cell-architecture` rules have nothing to govern here: `sandwich-phase-order`, `pure-decision-workflows`, `four-channel-contracts`, `pipeline-composition`, `ports-separate-from-layers`, and `staged-lawful-builders`. They apply the day a module in either package reads, decides, and writes against the outside world.
