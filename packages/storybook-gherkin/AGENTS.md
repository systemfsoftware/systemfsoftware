# AGENTS.md — `@systemfsoftware/storybook-gherkin`

Binds Gherkin specifications to Storybook 10 CSF-factory stories: specs in a `.stories.tsx` read like a `.feature` file and execute as play functions under the real browser runner. Root `AGENTS.md` governs.

## Rules

| ID       | Rule                                                                                                                                                                                                                                                                                                                                                                            | Gate                                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SG1**  | Built by tsdown alone (`tsdown && pnpm dts:check`); never add api-extractor. `dts:check` (`node scripts/check-dts.mjs`) fails only on diagnostics under our own `dist/` (third-party dts noise like `@vitest/expect`'s undeclared ambient `Chai` is not ours), keeps `composite: false` (stale `tsbuildinfo` replays mask config changes), and sets `skipLibCheck: false`.      | `pnpm --filter @systemfsoftware/storybook-gherkin build`                                                                                                         |
| **SG2**  | The story suite IS the test: specs written with this DSL compile, import, and run green under the consumer's real Storybook browser-mode runner via `test:browser` (`test/browser/spec.stories.ts`). No auxiliary test files, no raw `test()` inside the stories file, no stryker, no `test` script.                                                                            | `pnpm --filter @systemfsoftware/storybook-gherkin test:browser` (needs `pnpm --filter @systemfsoftware/storybook-gherkin exec playwright install chromium` once) |
| **SG3**  | Suite prose is Gherkin: stakeholder titles and step text, `capture('key')` holes in prose, assertions in step bodies. Scenario-outline rows become stories via DIRECT const exports (`export const X = Outline['row name']`) — never export the `.examples()` record itself (the CSF indexer turns it into a story with no play: a silent false green).                         | `pnpm --filter @systemfsoftware/storybook-gherkin test:browser`                                                                                                  |
| **SG4**  | tsgo policy covers `src` + `test/browser`: no `async`, no `new Promise`, no `setTimeout`/`Date`/`console` in tests — `Effect.sleep` and `performance.now()` are the allowed primitives, `Effect.runPromise` the only interpreter. Never relax the severity map. `vitest`/`@vitest/browser`/`@vitest/browser-playwright` stay on one minor+patch from the root catalog.          | `pnpm --filter @systemfsoftware/storybook-gherkin lint:tsgo` and `typecheck` exit 0                                                                              |
| **SG5**  | The embedded spec is the ONLY representation — a story using this DSL IS the `.feature`; never produce or require a parallel `.feature` file.                                                                                                                                                                                                                                   | `review`                                                                                                                                                         |
| **SG6**  | One interpretation edge: user code runs exactly once, at the play edge (`interpretPlay` via `Runtime.runPromiseExit` on the consumer-supplied runtime, errors flattened with `Cause.squash`). The `runStep` bridge's `Effect.runPromiseExit` runs only the pure `Deferred.await` signal — never user code. Never add a second run site for user code.                           | `review`                                                                                                                                                         |
| **SG7**  | Two error channels: declaration-time violations in `errors.ts` throw at module evaluation; run-time failures travel the typed `Step.run` channel or arrive as defects. A step handler's rejection is a defect and is NEVER wrapped in a tagged error — Storybook's Interactions panel matches `error.name === 'AssertionError'` and `expect(` prefixes to render matcher diffs. | `review`                                                                                                                                                         |
| **SG8**  | Abort interrupts steps: `interpretPlay` passes `context.abortSignal`; handlers observe `ctx.abortSignal` for their own cleanup (their `Promise` is abandoned, not cancelled); after abort the story-level `aborted` render phase is the source of truth, not a step's instrumenter status.                                                                                      | `review`                                                                                                                                                         |
| **SG9**  | `storybook` stays a peerDependency (`>=10.0.0`) even though `storybook/test` is imported at runtime — the consumer's install provides it. `effect` is a peer. `type-fest` is a regular dependency (its types appear in the shipped dts).                                                                                                                                        | `pnpm --filter @systemfsoftware/storybook-gherkin attw`                                                                                                          |
| **SG10** | `ScenarioOptions` is exact — `with` only; no options generic, no runtime spread of unknown keys. Storybook 10's CSF transformer discovers `tags`/`parameters`/`decorators`/`globals` only in exported object literals; anything copied onto a spec inside a `CallExpression` is invisible and silently yields zero stories.                                                     | `review`                                                                                                                                                         |
| **SG11** | Not Effect cell code: this package keeps its own minimal `oxlint.config.ts` and does NOT extend `@systemfsoftware/oxlint-config` — the cell rules are the wrong observer for library code.                                                                                                                                                                                      | `pnpm --filter @systemfsoftware/storybook-gherkin lint`                                                                                                          |
| **SG12** | No mutation gate: no `stryker.config.json`, never enrolled in a `mutate` glob — it holds no pure decision for a mutant to escape from.                                                                                                                                                                                                                                          | `pnpm check:stryker-mutate-scope`                                                                                                                                |

## Verification

```bash
pnpm --filter @systemfsoftware/storybook-gherkin build
pnpm --filter @systemfsoftware/storybook-gherkin lint:tsgo && pnpm --filter @systemfsoftware/storybook-gherkin typecheck && pnpm --filter @systemfsoftware/storybook-gherkin lint && pnpm --filter @systemfsoftware/storybook-gherkin attw
pnpm --filter @systemfsoftware/storybook-gherkin test:browser
```
