# @systemfsoftware/storybook-gherkin — Feature Specs → Stories

Owned under this org. Ported from WireBlast's `packages/storybook-gherkin`.

Binds Gherkin specifications to Storybook 10 CSF-factory stories: specs declared with this DSL in a `.stories.tsx` read like a `.feature` file and execute as play functions under the real browser runner.

## Delta

- **Not Effect cell code.** This package keeps its own minimal `oxlint.config.ts` and deliberately does **not** extend `@systemfsoftware/oxlint-config`: the cell rules (suffix provenance, workflow purity) are the wrong observer for library code. That is why `packages/storybook-gherkin/` sits under `TOOLING` in `scripts/guards/check-lint-coverage.mjs`.
- **Publishable, built by tsdown alone.** Ships `dist` (ESM + dts) and carries `attw`, `check:exports`, and `check:publish-config`. `build` is `tsdown && pnpm dts:check`.
- **Do not add api-extractor here.** The entry is a flat re-export barrel over the observers; tsdown's per-entry dts is the shipped types. `dts:check` (`node scripts/check-dts.mjs`, driving `tsc --noEmit -p tsconfig.dts.json`) is the only gate that reads the shipped dts — it sets `skipLibCheck: false` to simulate a strict consumer, and it is load-bearing.
- **`dts:check` is scoped to OUR dist.** The strict check drags third-party declaration files into the program: the `storybook/test` type surface flows through `@vitest/expect`, whose declarations reference an ambient `Chai` namespace they never declare (their own `@types/chai` dependency is installed but not ambient-visible, so `types: ["node"]` fails with TS2503). Adding a `@types/chai` devDependency we do not use would be cope; instead `scripts/check-dts.mjs` fails only on diagnostics whose file is under `dist/` (or is otherwise unattributable — a tsc crash or config error still fails), and treats errors in `node_modules` as third-party noise by construction. Our own dts is checked exactly as strictly as before; the manifest stays honest.
- **`dts:check` sets `composite: false`.** The base preset enables composite, whose incremental `tsbuildinfo` replayed a stale program and masked a config change (measured: deleting the buildinfo flipped the same config from red to green). The dts project is standalone — nothing references it — so composite buys nothing and costs determinism.
- **M1 This package is a test library — its own tests are the minimal story-run.** The test is that specs written with this DSL compile, import, and run green under the consumer's real Storybook browser-mode runner. Since 2026-08-09 that test lives in-repo as `test/browser/spec.stories.ts`, run by the `test:browser` script (`@storybook/addon-vitest` browser mode; NOT part of `check:ci` — a workflow gated on this package's own paths runs it in CI). The stories ARE the tests: no auxiliary test files, no raw `test()` calls inside the stories file, no stryker, no `test` script (only `test:browser`). The runner-inexpressible behaviors (error identity through the play edge, abort interruption, declaration-time channels) are verified by a consumer exercise recorded under `docs/residual-review-findings/` — do not rebuild that coverage in-repo. Root Global Forbidden Patterns bans simulated DOM outright; the suite uses the real chromium DOM, which is the point.
- **M1a The suite's prose is Gherkin, not identifiers.** Titles and step text are stakeholder prose (`Alice receives a greeting that names her`, `the user alice has an account`); captures are `capture('key')` holes that render into the prose; assertions live in the step bodies. Scenario-outline rows become stories via DIRECT const exports (`export const AliceIsGreetedByName = Outline['Alice is greeted by name']`) — never export the `.examples()` record itself: the CSF indexer turns it into a story with no play, a silent false green.
- **M1b The tsgo policy covers the test files.** `tsconfig.json` includes `test/browser`, so `lint:tsgo` and `typecheck` gate the suite: no `async`, no `new Promise`, no `setTimeout`/`Date`/`console` in tests — `Effect.sleep` and `performance.now()` are the allowed primitives, and `Effect.runPromise` is the only interpreter used by tests. `vitest`/`@vitest/browser`/`@vitest/browser-playwright` must stay on one minor+patch (R-HARD-3); they resolve together from the root catalog. Playwright browsers are installed explicitly (`pnpm --filter @systemfsoftware/storybook-gherkin exec playwright install chromium`, postinstall blocked in `pnpm-workspace.yaml` `allowBuilds`) and cached in CI on the lockfile hash.
- **M2 Breaking changes are encouraged.** Root release policy applies in full: delete old API paths outright, migrate every caller in the same change, NEVER keep compat shims or deprecated aliases.
- **`ScenarioOptions` is exact — `with` only; no options generic, no runtime spread.** The three public option types (`ScenarioFn`, `OutlineFn`, `OutlineBuilder`) carry no `TOptions extends ScenarioOptions` generic, and the runtime does not spread unknown keys onto the returned spec (`omitWith` is gone). Storybook 10's CSF transformer discovers `tags`/`parameters`/`decorators`/`globals` by static analysis of exported object literals (`isObjectExpression`); anything copied onto a spec inside a `CallExpression` is invisible to it, so tag-based filtering silently yields zero stories with no error. The exact type makes passing those annotations through `f.scenario()`/`f.scenarioOutline()` options a compile error; consumers attach them via the object-literal spread pattern (`{ ...f.scenario(…), tags: […] }`) the transformer can see. Never re-add an options generic, an `& Omit<TOptions,'with'>` on a spec return type, or an `omitWith`-style spread to "accept" annotations — that reopens a silent bypass the published type exists to prevent. A regression compiles green and ships no script gate (the exact type signature is the published enforcement, REPO-S6), so the reviewer confirms those three types stay generic-free and `omitWith` stays deleted.
- **M4 The embedded spec is the ONLY representation.** A story using this DSL IS the `.feature` — NEVER produce or require a parallel `.feature` file for a storied app; duplicate representations drift.
- **One interpretation edge.** Two run sites exist by design: `Runtime.runPromiseExit` in `interpretPlay` (`src/feature.observer.ts`) — user code, consumer-supplied runtime (`feature(meta, { runtime })`, default `Runtime.defaultRuntime`), flattened via `Cause.squash` so the original error instance reaches Storybook — and `Effect.runPromiseExit` in `runStep`'s bridge, the sole allowed exception, running only a pure `Deferred.await` signalling effect, never user code. Invariant: user code is interpreted exactly once, at the play edge; never add a second run site for user code.
- **Two error channels.** The declaration-time violations in `errors.ts` (all except `CaptureDecodeFailed`) throw during module evaluation and fail the Storybook import. Run-time failures travel the typed `Step.run` channel (`CaptureDecodeFailed`) or arrive as defects — a step handler's rejection is a defect, and must never be wrapped in a tagged error: Storybook's Interactions panel matches `error.name === 'AssertionError'` and `expect(` message prefixes to render matcher diffs, and a wrapper breaks that.
- **Abort interrupts steps.** `interpretPlay` passes `context.abortSignal` to the run; interruption propagates to the in-flight step's child fiber. Behavioral break: an abandoned story's steps previously ran to completion; now remount, navigation, and HMR teardown interrupt them. Three follow-on contracts: (a) a step handler's own `Promise` is abandoned, not cancelled — handlers must observe `ctx.abortSignal` for cleanup; (b) after abort, a step's per-call instrumenter status may read `done` despite incomplete work — the story-level `aborted` render phase is the source of truth; (c) in Storybook's interactions debugging mode (step-through), tracked calls inside a step run outside the step's ancestor window because the step body starts before the debugger pushes the step context — debug-mode nesting is not supported.
- **No mutation gate.** No `stryker.config.json`; the package must never be enrolled in a `mutate` glob (root mutation rule — `check:mutate-scope`).
- **`storybook` is a peerDependency** (`>=10.0.0`) even though `storybook/test` is imported at runtime (`screen`, `within`) — the consumer's Storybook install provides it. `effect` is a peer, matching the org's effect packaging. `type-fest` is a regular dependency: its types appear in the shipped dts (`CapsOf` via `Simplify`/`UnionToIntersection`), so consumers need it resolvable.
- **Dependencies flow through the root catalog.** `storybook: ^10.5.0` and `type-fest: ^5.8.0` match the versions WireBlast's catalog resolved; neither needs WireBlast's `patches/storybook@10.5.0.patch` (that patch edits runtime JS chunks only, and this package never runs storybook — it only typechecks against it).
- **tsgo policy is the design driver.** This package opts into `packages/tsconfig/effect.json` (2026-08-09), where `asyncFunction` and `newPromise` are `error`; the package's `lint:tsgo` script runs under `pnpm check:ci` via turbo. The 2026-08-09 Effect-composition refactor exists to satisfy those rules — a keyword-dropping quick fix was tried and reverted; only real Effect composition passes. Keep `lint:tsgo` green; do not relax the severity map.
- **`typecheck` and `lint:tsgo` cover `src` + `test/browser`** (`include: ["src", "test/browser"]`); `tsconfig.build.json` (what tsdown emits dts from) stays `src`-only, so the suite's dev-only imports never reach the shipped dts.
