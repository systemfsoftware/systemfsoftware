# AGENTS.md — `@systemfsoftware/stryker-js-plugin-api`

> **Location:** `packages/testing/mutation/stryker-js/plugin-api/` — the contract an outside adopter implements a Stryker plugin against.

This package is owned outright (`REPO-O1`). It began as a port of `@stryker-mutator/api`, which is history and not governance: refactor it like any other package here. The option set is this package's own — one Effect Schema in `src/core/stryker-options.schema.ts` replaces a vendored `schema/stryker-core.json` plus a `json-schema-to-typescript` codegen chain, and the JSON Schema document consumers validate against is derived from it with no file read. Gated by `pnpm lint`, `pnpm typecheck` and `pnpm build`.

Deltas from root:

- **No `stryker.config.json`** — this is an API/types cell, so it decides nothing and must not be enrolled in mutation (root mutation rule — `check:mutate-scope`).
- **A plugin is a `Layer`, and the sandbox directory is a service.** `declarePlugin(kind, name, layer)` in `src/plugin/Plugins.ts` is how a contribution is declared; the engine composes the layers and reads each port out of the built `Context`. There is no token map and no injected-value container. A plugin that needs the sandbox directory requires `SandboxDirectory` (`src/plugin/SandboxDirectory.ts`, a `Context.Service`) and receives it because the engine provides it — never by inferring it from `process.cwd()`. That service is provided only in sandbox worker processes, so a plugin running in the main process, such as a reporter, cannot require it: nothing supplies it there and the layer will not close.
- **The option set is ONE Effect Schema, derived — never generated.** `src/core/stryker-options.schema.ts` declares every option name, type, optionality and default, and nothing else: `strykerCoreSchema` is the JSON Schema document derived from it via `S.toJsonSchemaDocument` (no file read) and lives in `src/core/stryker-core-schema.ts`, because a document is a _use_ of a schema and a `*.schema.ts` exports only declarations — the gate is `schema-file-exports-schemas-only`, and a tool that reads every exported schema in the package (the generated law suite) breaks outright when handed a document. Both are re-exported from `src/core/index.ts`, so the published names are unchanged. There is no `schema/` directory, no `src-generated/`, no `generate` script, and no `json-schema-to-typescript`. Extend the schema module and the document follows; the gates are `pnpm lint`, `pnpm typecheck`, `pnpm build`.
- **`core.d.ts` is deleted.** It existed as a shim so `--moduleResolution node` could resolve `@stryker-mutator/api/core` for JSDoc `import('.../core')` annotations. This package is ESM-only with a tsdown-generated exports map, so `./core` resolves through `exports`, and the shim's `./dist/src/core/index.js` target is a layout the build no longer produces.
- **Build layout is `dist/<subpath>/index.mjs`, not `dist/<subpath>.mjs`.** Kept for convention with the sibling packages in this subsystem; no entry has a runtime file dependency now, so the entries could be flattened without breaking the `core` subpath.
