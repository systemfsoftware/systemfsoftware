# AGENTS.md — `@systemfsoftware/stryker-js-cli`

The `stryker` bin: NDJSON run-event framing, mode/colour detection, signal handling, drain-before-exit, classed exit code. Parent: `packages/stryker-js/AGENTS.md`.

## Rules

| ID         | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                               | Gate                                                                                                                                                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CLI-B1** | Never drop the `prepare` script (`tsdown`) and never point `bin` at a committed shim: the bin target is gitignored `dist/main.mjs`, and pnpm links `.bin` shims before and after lifecycle scripts — without `prepare` the shim targets nothing and `stryker run` dies with `stryker: not found` on a fresh install.                                                                                                                               | Fresh `pnpm install` followed by `pnpm --filter @systemfsoftware/stryker-js-cli exec stryker --help` exits 0                                                                                                                                   |
| **CLI-M1** | Mutation scope is whatever `stryker.config.json#mutate` currently declares — read the config, never trust a filename written in prose.                                                                                                                                                                                                                                                                                                             | `git show HEAD:packages/stryker-js/stryker-js-cli/stryker.config.json` prints the live `mutate` array; `pnpm --filter @systemfsoftware/stryker-js-cli mutation` is its only reader                                                             |
| **CLI-S1** | `package.json#exports` is tsdown-generated (REPO-S4) and carries only `./package.json`: this package is a bin and publishes no program entry, but a tool that reads a package's manifest by specifier still finds it (`exports.packageJson`, on by default — the tshy convention). Author it in `tsdown.config.ts` as `exports: { packageJson: true, exclude: [<every entry>], bin: { stryker: './src/main.ts' } }`; never hand-edit the manifest. | `node -p "JSON.stringify(require('./packages/stryker-js/stryker-js-cli/package.json').exports)"` prints `{"./package.json":"./package.json"}`                                                                                                  |
| **CLI-D1** | The bundle imports nothing but `node:` builtins, which is what licenses the manifest's empty `dependencies`: each of them is a build input, never a runtime need. A dependency that cannot be inlined is a build error, not a new runtime dependency.                                                                                                                                                                                              | `pnpm --filter @systemfsoftware/stryker-js-cli build` fails on any emitted import that is not `node:` (`deps.onlyImport: [/^node:/]` in `tsdown.config.ts`)                                                                                    |
| **CLI-D2** | The parser is the WASI build, aliased from `oxc-parser`; a platform-native binding cannot be inlined once for every platform. The alias asserts parser and binding versions are equal, and the `.wasm` ships beside the chunks (`files` is `dist`). The instrumenter parses through the binding's synchronous entry, so the async pool's `wasi-worker.mjs` is neither emitted nor needed.                                                          | `pnpm --filter @systemfsoftware/stryker-js-cli build` throws on a version mismatch; `test -f packages/stryker-js/stryker-js-cli/dist/parser.wasm32-wasi.wasm` passes after it; `node dist/main.mjs --version` writes nothing to standard error |
| **CLI-D3** | The engine loads the HTML reporter as a plugin module, so it ships as its own entry referenced by a relative URL, and its client bundle is baked at build time by `define` — a bundled reporter cannot resolve that asset from disk.                                                                                                                                                                                                               | `pnpm --filter @systemfsoftware/stryker-js-cli exec node -e "const s=require('fs').readFileSync('dist/reporters/html.mjs','utf8'); if(!s.includes('MutationTestElements')) process.exit(1)"` exits 0                                           |
| **CLI-D4** | The contract lane installs the packed executable alone and offline; the other workspace packages live in their own root, used only by scenarios that probe them. Packages installed beside the executable answer its resolution for it, which is what made a packed executable missing its own WebAssembly module pass.                                                                                                                            | `pnpm --filter @systemfsoftware/stryker-js-cli test:contract` — its artifact scenarios assert the install closure and a run rendering both reports                                                                                             |
| **CLI-L1** | `oxlint.config.ts` extends `oxlint-config/base` and registers the effect-entrypoint and test-placement plugins explicitly — they are not in the `effect-dmmf` bundle, and this package's subject is an interpretation edge.                                                                                                                                                                                                                        | `pnpm --filter @systemfsoftware/stryker-js-cli lint` exits 0                                                                                                                                                                                   |
