# AGENTS.md — `@systemfsoftware/stryker-js-cli`

The mutation host, and the `stryker` bin: it owns run orchestration (`src/run/`), the instrumenter core (`src/instrument/`), the builtin and html reporters (`src/report/`), the Node binding (`src/platform/`), and the worker entries (`src/workers/`). NDJSON run-event framing, mode/colour detection, signal handling, drain-before-exit, and the classed exit code all live at the `src/main.ts` edge. Parent: `packages/stryker-js/AGENTS.md`.

## Rules

| ID         | Rule                                                                                                                                                                                                                                                                                                                                                                   | Gate                                                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CLI-B1** | Never drop the `prepare` script (`tsdown`) and never point `bin` at a committed shim: the bin target is gitignored `dist/main.mjs`, and pnpm links `.bin` shims before and after lifecycle scripts — without `prepare` the shim targets nothing and `stryker run` dies with `stryker: not found` on a fresh install.                                                   | Fresh `pnpm install` followed by `pnpm --filter @systemfsoftware/stryker-js-cli exec stryker --help` exits 0                                                                       |
| **CLI-M1** | Mutation scope is whatever `stryker.config.json#mutate` currently declares — read the config, never trust a filename written in prose.                                                                                                                                                                                                                                 | `git show HEAD:packages/stryker-js/stryker-js-cli/stryker.config.json` prints the live `mutate` array; `pnpm --filter @systemfsoftware/stryker-js-cli mutation` is its only reader |
| **CLI-S1** | `package.json#exports` and `publishConfig.exports` are tsdown-generated (REPO-S4); change the `exports` block in `tsdown.config.ts` (`exclude` names every non-`main` entry, `bin: { stryker: './src/main.ts' }`).                                                                                                                                                     | `pnpm --filter @systemfsoftware/stryker-js-cli build` regenerates cleanly and the tarball carries `main` plus the worker and preset entries                                        |
| **CLI-L1** | `oxlint.config.ts` extends the house `all` preset — the absorbed engine's own posture — and adds only the fixtures ignore path; `src/instrument/oxlint.config.ts` carries the absorbed instrumenter's narrower override (`oxlint-config/base` plus `ban-classes`). Neither may be weakened to make a check pass, and neither carries an `eslint-disable`-style escape. | `pnpm --filter @systemfsoftware/stryker-js-cli lint` exits 0, and `grep -rn "eslint-disable\|oxlint-disable" src` is empty                                                         |
| **CLI-P1** | Every adapter — checker, test runner, ignorer, evaluator, parser, reporter — is reached by loading a plugin module by string and calling the contributed plain factory; there is no compiled-in registry and no import of a first-party adapter package from `src/`.                                                                                                   | `grep -rn "stryker-js-typescript-checker\|stryker-js-vitest-runner" src` is empty; the plugin suites exercise module-string loading                                                |
| **CLI-P2** | `effect` is the host's own runtime and is bundled into `dist` (`deps.alwaysBundle` in `tsdown.config.ts`); it must never appear as a dependency a consumer installs, and no plugin package declares it as a peer.                                                                                                                                                      | `pnpm --filter @systemfsoftware/stryker-js-cli attw --pack .` passes; `node -e "console.log(require('./package.json').peerDependencies)"` is empty                                 |
| **CLI-I1** | The instrumenter's format table is fed from `Parser` contributions (extension → parse function) supplied by the caller; an extension with no contribution fails as the named `ParserNotFound` config fault, never a crash. Html and svelte parsing live in their own plugin packages and are not imported here.                                                        | `grep -rn "svelte\|angular-html-parser\|parseHtml" src/instrument` is empty; the parser-resolution suite asserts `ParserNotFound`                                                  |
