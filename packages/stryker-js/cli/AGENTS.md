# AGENTS.md — `@systemfsoftware/stryker-js-cli`

> **Location:** `packages/stryker-js/cli/` — the stryker command-line interface, extracted out of `packages/stryker-js/core/`. Universal agent rules live in the root `AGENTS.md`; this file carries only `stryker-js-cli/`-specific deltas.

## Why this package exists

The `stryker` bin's home. Core (`@systemfsoftware/stryker-js-core`) is the mutation engine; this package owns the terminal-facing half — NDJSON run-event framing on stdout, mode and colour detection, signal handling, drain-before-exit, and the classed exit code — and reaches core through the injected run-event sink. The bin name is `stryker`, unchanged from core's, so consumer script text does not move.

## Bin and entry point

`package.json` declares the bin `stryker` as dist/main.mjs (built output, absent until a build) and `exports` exposes only `./package.json`. The composition root is `src/main.ts`, a shebang'd entry that checks `strykerEngines.node` with semver, builds `StrykerCliExecutorDepsLive` from `OutputModeProbeLive` and `RunEventStreamLive`, and interprets `strykerCliEffect(process.argv, …)` through `NodeRuntime.runMain`, its `teardown` carrying the resolved exit code. The packed bin is runnable, and the contract lane exercises it end to end — 24/24 scenarios pass in real containers against the packed tarball.

## Mutation config

`stryker.config.json` exists and scopes `mutate` to `src/survivors.workflow.ts`, the package's decision cell; the gate runs through the `mutation` and `mutation:full` scripts. REPO-S5 (root `AGENTS.md`) forbids shell cells in a mutation surface, and `scripts/guard-mutate-scope.mjs` fails any config whose `mutate` glob names a forbidden cell — so widen the glob only for a new genuine `*.workflow.ts` cell, never to sweep the whole `src/` tree.

## Lint enrolment

`oxlint.config.ts` extends `@systemfsoftware/oxlint-config/base`, which delivers the cell-suffix, property-testing, test-hygiene, and test-placement families through the `effect-dmmf` bundle. The effect-entrypoint rules are registered explicitly on top — they are not in that bundle, and this package's entire subject is an interpretation edge. Test-placement is registered explicitly alongside them, mirroring the sibling core package's registration shape.

## Exports field

`package.json#exports` and `publishConfig.exports` are regenerated by tsdown on every build (REPO-S4). Never hand-edit either — change the `exports` block in `tsdown.config.ts` instead, which here declares `exclude: ['main']` so the entry is not re-exported and `bin: { stryker: './src/main.ts' }` so the bin field is emitted from source.
