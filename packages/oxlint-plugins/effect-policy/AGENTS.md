# AGENTS.md — `effect-policy/`

> Shared rule-authoring conventions: `packages/oxlint-plugins/AGENTS.md`.

- **PP1 — Obligation, not single-export:** keep `policy-combinator-export` requiring ≥1 rank-2 combinator export (generic with an Effect-typed first parameter, or a value annotated with a `*Policy` type). Never ban additional non-function exports — a stateful policy legitimately exports an `Effect<P>` factory, a `Layer`, or Xi error classes alongside the combinator.
- **PP2 — PO1 import set is closed:** match exactly the skill's enumerated cells (schema, shape, state, workflow, executor, store, acl, handler, middleware, adapter, service, shell, use-case, daemon, repository). Never add `.policy` (composition via `andThen`) or `.kernel` (domain-blind utilities) — their deliberate absence is proven by the suite's valid cases, not a comment.
- **PP3 — Error-channel vocabulary is the PO3 dont-list:** ban exactly the Effect APIs that rewrite or swallow E (mapError, mapBoth, orElse, orElseFail, orElseSucceed, orDie, orDieWith, catchAll, catchCause, catchTag, catchTags, …). Never ban `Effect.tapError`, `Effect.retry`, `Effect.timeout`, `Effect.timeoutFail`, or `Effect.withConcurrency` — observation and refusal-adding are the policy's own business (a circuit breaker counts failures via tapError).
- **PP4 — Path segments gated under `src` only:** check junk-drawer segments (core, shell, utils, helpers, entities, components, hooks, controllers, jobs, db, migrations, service, manager, use-case, repository) only after the last `src` segment. Never check absolute-prefix segments (false positives on a repo root that happens to match) or the positional PO5 clauses (types/ above a capability, central routes/) — they need capability topology the file alone does not carry.
- **PP5 — Type-checker gates are not lint rules:** leave PO2 (same A out) and the parametricity half of PO1 to the compiler and the cell's property-test laws. Never emulate type equality on the AST — it cannot tell `Effect<A, E | Xi, R>` from `Effect<string, E, R>`.
- **PP6 — Suffix gate + data assertions:** gate every rule on `context.filename` ending `.policy.ts`; assert report `data` fields in every RuleTester case. Never assert on path prefixes — RuleTester resolves filenames into node_modules.

Deliberate non-gates (spec'd but not lint-able here): PO2 same-A-return, PO3 error identity, and the operational laws — type-checker or property-test territory.
