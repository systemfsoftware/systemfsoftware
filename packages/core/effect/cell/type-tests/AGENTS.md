# AGENTS.md — `@systemfsoftware/effect-cell-type-tests`

> **Delta**: the type-level observer of a Cell description — a derived consumer whose whole output is
> generated by walking `Cell.vocabulary`, and whose checker is TypeScript rather than a runtime
> assertion. Root AGENTS.md governs.

## What makes this package different

```yaml
rules:
  - id: CELL-TT1
    title: test-types/ is generated and untracked — never hand-edit it, never commit it
    do: regenerate with `pnpm --filter @systemfsoftware/effect-cell-type-tests generate`; both
      `typecheck` and `test:types` run that generation first, so a stale suite cannot be checked
    dont: edit a file under `test-types/`, commit one, or "repair" the gitignore entry that keeps it
      out of the tree
    harm: the suite is the walk's output. A committed one could be hand-edited into a second
      declaration wearing a generated file's name, and a drift gate comparing bytes is the wrong
      instrument for it — there is no artifact to compare when the artifact is never stored
    check: "`git check-ignore -v test-types/Vocabulary.tst.ts` reports the ignore rule, and a hand
      edit to a file under `test-types/` is gone after the next `test:types` — the regeneration
      overwrites it rather than reporting it"

  - id: CELL-TT2
    title: Every emitted claim is a function of the walk
    do: derive each assertion from `Cell.vocabulary` — one block per phase for its name, kind and
      convention, a pairing matrix for intra-layer order, the module name, the I/O classification
    dont: write a phase name, kind, order, module name or I/O cell as a literal in
      `scripts/generate-type-tests.ts`
    harm: a literal in the generator is a claim the description cannot move, so the suite would keep
      passing over a vocabulary that had changed underneath it
    check: "`grep -nE \"'(read|decode|decide|encode|write|pure|impure|store|adapter)'\" scripts/generate-type-tests.ts` returns nothing; review — no phase axis literals in generator"
  - id: CELL-TT3
    title: scripts/ is Deno's, not tsc's
    do: keep the generator a Deno script with a shebang and least-privilege flags, checked by
      `pnpm --filter @systemfsoftware/effect-cell-type-tests check:scripts`
      (`deno check` + `deno lint` against `scripts/deno.jsonc`)
    dont: "add `scripts` to `tsconfig.node.json`'s `include`, or drop `nodeModulesDir: \"manual\"` from
      `scripts/deno.jsonc`"
    harm: "the generator uses `Deno` globals, so pulling it into the node TS program fails
      `check:project-references` with TS2304 — measured, and masked for a while by a turbo cache
      hit. Without `nodeModulesDir: \"manual\"` the bare workspace import fails as `not a dependency`"
    check: "`pnpm --filter @systemfsoftware/effect-cell-type-tests check:scripts` exits 0 and
      `pnpm check:project-references` reports this project compiling clean"

  - id: CELL-TT4
    title: TypeScript is the oracle, and it must be able to disagree
    do: keep the emitted claims falsifiable by the compiler — reversing the walked order must make
      the emitted pairings uncallable
    dont: emit only assertions that hold by construction, or soften a claim to `unknown`/`any` to
      make a generated line compile
    harm: an oracle that cannot fail is a tautology with a passing badge; this consumer exists
      precisely because its checker is not the runtime fold that produced the value
    check: review — reversing the walk in the generator makes `pnpm --filter @systemfsoftware/effect-cell-type-tests test:types` fail (measured at 7 failing assertions)
```

## Dependency edge

`@systemfsoftware/effect-cell-type-tests -> @systemfsoftware/effect-cell-types`, one way. Nothing in
the description package may import this one; a back-edge closes a turbo `#build` cycle through
`oxlint-config`.
