# AGENTS.md — `@systemfsoftware/effect-daemon-spec`

> **Delta**: API-surface enforcement and tsdown↔api-extractor pipeline specifics. Root rules unchanged.

## Public API Contract

`etc/effect-daemon-spec.api.md` IS the public API surface. **MUST** treat it as a committed snapshot.

| Trigger                                 | Required Action                                        |
| --------------------------------------- | ------------------------------------------------------ |
| Change to anything exported by `mod.ts` | `pnpm build && pnpm api:update`, commit `etc/*.api.md` |
| New `Warning: (ae-forgotten-export)`    | **MUST** export the type from `mod.ts` OR inline it    |
| `*_base` warning on a NEW class         | **NEVER** suppress — refactor with named base const    |

**Enforcement:** `pnpm api:check` (no `--local`) compares live analysis to the committed report; non-zero exit if stale. Wired into root `pre-push` and CI.

## Accepted Noise

11 `Warning: (ae-forgotten-export) ... _base` entries in `etc/effect-daemon-spec.api.md` are synthetic intermediates from effect's `Schema.Class` / `Context.Tag` / `TaggedError` factories. **NEVER** delete these from the report; they are baseline. Adding a new `*_base` warning requires either (a) extracting a named base const at the source, or (b) explicit reviewer approval recorded in the PR.

## Pipeline Ordering

`pnpm build` MUST precede `pnpm api:check` / `pnpm api:update`. Build sequence: `tsdown` → `dist/index.d.ts` → `api-extractor` → `dist/effect-daemon-spec.d.ts` (rollup) + `etc/*.api.md` (report).

## Exports Field

`package.json#exports` is regenerated by tsdown on every build. **NEVER** hand-edit `exports` or `publishConfig.exports` — modify the `injectApiExtractorTypes` callback in `tsdown.config.ts` instead. New subpath exports require an entry in `apiExtractorRollups` (`tsdown.config.ts:5`).

| Field                        | Source                                |
| ---------------------------- | ------------------------------------- |
| `exports['.']` ordering      | `tsdown.config.ts` customExports      |
| `exports['.'].types`         | `apiExtractorRollups[subpath]`        |
| `publishConfig.exports['.']` | Same callback, dev condition stripped |

`types` MUST appear before `default` per Node.js conditional-exports resolution.

## Module Don'ts

- **NEVER** add `effect` to `bundledPackages` in `api-extractor.json` — peer dep, would freeze a snapshot of effect's types into our rollup.
- **NEVER** set `addToApiReportFile: false` on `ae-forgotten-export` without a plan to fix the 11 baseline `*_base` warnings.
- **NEVER** commit `temp/` (api-extractor scratch — gitignored at package level).
- **NEVER** gitignore `etc/` — the API report is the contract.
- **NEVER** import internals via subpath (e.g. `@systemfsoftware/effect-daemon-spec/internal/...`); only the `.` entry is exported.
