Shared rule-authoring conventions for every oxlint plugin in this subtree. Root `AGENTS.md` governs; each package leaf carries only its own delta.

## Topology

The subtree is a **fragment library**. Each plugin package exports `./preset` — a config fragment that self-registers: `{ jsPlugins: [import.meta.resolve('<own package name>')], rules: <own configs.recommended.rules> }`, plus any file-glob `overrides` it needs; a fragment never carries `plugins` or `ignorePatterns`. A per-package registration test (`<pkg>/src/__tests__/preset.test.ts`) pins the fragment to its derivation.

Two canonical roots live in `@systemfsoftware/oxlint-preset` (`src/canonical.ts`, `src/instrument.ts`):

- `.` — the strict set for product code: the recommended stock tier, the ten leaf fragments (effect-native, tag-discipline, structure, effect-schema, effect-workflow, property-testing, test-hygiene, test-placement, cell-vocabulary, effect-entrypoint), `correctness: error`, and the three pure-core rules — `no-ternary`, `typescript/switch-exhaustiveness-check`, `no-restricted-imports` — plus `complexity` ceilings of max 2 under `src/` and max 1 in `*.workflow.ts`.
- `./instrument` — the set for a package whose subject is the linter: `extends: [recommended]` plus the stock plugin namespaces and `correctness: error`, and no product rules. The subtree baseline (`packages/oxlint-plugin/oxlint.config.ts`) extends it.

`@systemfsoftware/all` is a pure re-export of the preset's default export plus `defaultIgnores` (nine globs, `src/default-ignores.ts`); it declares nothing of its own.

`@systemfsoftware/oxlint-config/base` is the transitional survivor: re-derived from nine leaf fragments (`src/oxlint-config.base.ts`; cell-vocabulary excluded — OX-DL1), it holds the 19 ex-base consumers at today's strength and dies by contract **F4** of `docs/plans/2026-09-12-strict-enrollment.md`, which flips each parked consumer onto its classified root before the package is deleted whole.

Each rule is registered by the package that owns it, so every rule id is `<owning package>/<rule>`; the two re-key aggregates — `@systemfsoftware/oxlint-plugin` and `@systemfsoftware/oxlint-plugin-effect-dmmf` — were deleted (`.changeset/all-canonical-cutover.md`). A `// oxlint-disable` comment, however, must name the short display namespace oxlint derives from the package name — `@systemfsoftware/structure/ban-classes`, not the package namespace `@systemfsoftware/oxlint-plugin-structure/ban-classes`; the long form parses and suppresses nothing (`docs/solutions/build-errors/a-disable-comment-names-the-config-key.md`).
