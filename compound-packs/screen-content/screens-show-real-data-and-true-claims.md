---
title: A user-facing screen shows only real data and claims the deployed product delivers, never raw errors or stock AI copy
applies_when:
  - writing copy, headings, example data or calls to action on a user-facing screen
  - designing an empty, loading or error state
tags: [content, copy, claims, error-states]
---

Never ship an invented number, user, count, testimonial, logo, review or activity on a deployed screen; every figure a deployed screen shows is recorded or live data.

Never let a heading, sentence, example or call to action claim behaviour the deployed product does not perform; a call to action leads only into a flow that completes on the deployed product.

Never show raw error text, a stack trace, failed tool-call output or a bare 'Unavailable' as a failure state; a failure state says what happened in the person's terms and what they can do next.

Never ship copy built on metaphor taglines, rule-of-three lists, 'not X but Y' contrasts, em-dash cadence or inflated adjectives.

The review judge decides whether a claim holds and whether copy matches these patterns. It decides from the rendered screen and a recorded run of the claimed flow on the deployed product, and it never accepts the author's description as proof. An uncertain verdict escalates to a person and never passes.

Gate: judge
