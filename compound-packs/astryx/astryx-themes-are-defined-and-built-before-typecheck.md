---
title: An Astryx theme is defineTheme over a base theme, and its CSS is generated by a theme build that runs before typecheck and build
applies_when:
  - adding or editing an Astryx theme, its accent, typography, radius, motion or per-component overrides
  - setting up an app that depends on @astryxdesign/core and needs its own brand
  - overriding --color-* or other Astryx custom properties in a stylesheet to change the brand
tags: [astryx, theme, defineTheme, build, tokens]
---

A brand is a theme, not a stylesheet of overrides. Astryx derives its whole token set (color ramps, contrast, type scale, radius, motion) from a theme definition and emits it as CSS scoped to the theme; hand-written `:root { --color-... }` overrides fight that output, miss the derived tokens and drift between light and dark.

1. **Define the theme with `defineTheme`, extending a base theme.** One source file default-exports `defineTheme({ name, extends: <base theme>, typography, motion, radius, color, components })`. Only what differs from the base is written. Per-component overrides go under `components`, keyed by the component and its variant, with values that are tokens (`var(--text-display-1-size)`) or plain numbers.

   ```ts
   import { defineTheme } from '@astryxdesign/core/theme'
   import { neutralTheme } from '@astryxdesign/theme-neutral'

   // Placeholder values: each repo's own name, families and accent live in that repo, not in this pack.
   export default defineTheme({
     name: 'app',
     extends: neutralTheme,
     typography: { body: { family: '<body family>', fallbacks: 'system-ui, sans-serif' } },
     color: { accent: '<accent>' },
   })
   ```

2. **Generate the theme's CSS and module with the CLI.** A `theme:build` package script runs `astryx theme build <theme source> --out <theme>.css`, which writes the CSS and the typed theme module beside it. The global stylesheet imports the generated CSS after `astryx.css` and before `tailwind-theme.css`, so it lands in the `astryx-theme` layer of the declared order (pack: astryx, astryx-is-consumed-as-prebuilt-css-under-tailwind-with-one-layer-order.md); the app entry and the Storybook preview load that stylesheet, and the root's `Theme` takes the generated theme object (pack: astryx, astryx-styles-and-providers-load-at-every-root.md).
3. **The theme build runs before typecheck and before build.** Wire it as `pretypecheck` and `prebuild` (or as an upstream task of both in the task runner), so neither can run against a missing or stale theme.
4. **Generated files are not committed.** The generated CSS, module and declaration files are ignored by git and rebuilt. A committed copy goes stale the first time someone edits the source and forgets to rebuild.
5. **No brand overrides outside the theme.** `--color-*` and the other Astryx custom properties are never redefined in `:root` or a global stylesheet; a change to the brand is a change to the theme source.

Gate: the typecheck and the bundler, by construction. Because the generated module is ignored by git and imported by the root, a checkout that skipped `theme:build` fails module resolution in `tsc` and in the build, and `pretypecheck`/`prebuild` make the build step run first. Rule 5 has no gate yet; the fact it would read is, from the emitted stylesheets, a declaration of an Astryx custom property outside the `astryx-theme` layer.
