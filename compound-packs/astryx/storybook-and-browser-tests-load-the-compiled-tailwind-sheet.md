---
title: Storybook and browser tests load the compiled Tailwind sheet, generated by a compile-css script that runs before every test and is never committed
applies_when:
  - setting up or editing the Storybook preview or the Vitest browser setup of an app that uses Tailwind classes or Astryx
  - adding or changing a test script, a prepare script or the CI step that runs stories or browser tests
  - a story or a browser test renders Tailwind classes or Astryx components unstyled while the running app is styled
  - adding a new app or package whose stories render Tailwind classes
tags: [astryx, tailwind, storybook, vitest, browser-tests, css]
---

The app's bundler plugin compiles the Tailwind sheet for the app. Storybook's preview and a Vitest browser run do not go through the app's entry, so unless they load a sheet themselves their first paint is unstyled: stories pass on a plain page and tests measure layout that production never shows. The fix is one compiled sheet, generated by a script, imported by both.

1. **A `compile-css` script in the app's `package.json`** runs the Tailwind CLI over the global stylesheet from the layer-order rule (pack: astryx, astryx-is-consumed-as-prebuilt-css-under-tailwind-with-one-layer-order.md) and writes one file, for example `"compile-css": "npx @tailwindcss/cli -i ./src/styles/global.css -o ./tests/dist/tailwind-compiled.css"`. `@tailwindcss/cli` is a devDependency of the app (`pnpm exec tailwindcss` with the same `-i` and `-o` is the same CLI). The output goes under a `dist/` folder next to the tests or `.storybook`.
2. **The output is gitignored.** The compiled sheet is a build artifact; its folder (`tests/dist/`, `.storybook/dist/`) is in `.gitignore`. A committed copy goes stale the first time someone adds a class or edits the stylesheet.
3. **It is regenerated before tests, not remembered.** Either `prepare` runs `compile-css` (so a fresh install produces the sheet) or every test script chains it (`"test": "pnpm compile-css && vitest run"`, and the same for each variant: coverage, storybook, watch, changed). A test script that runs `vitest` alone can read a sheet from last week's classes. CI runs the same scripts, not a bare `vitest`.
4. **Both entry points import it as their first line.** The Storybook preview (`.storybook/preview.ts`) imports `./dist/tailwind-compiled.css`, and so does the Vitest browser setup file (the `setupFiles` entry, for example `tests/setup.ts` or `.storybook/vitest.setup.ts`). The preview also wraps stories in the providers (pack: astryx, astryx-styles-and-providers-load-at-every-root.md). With both imports, a story rendered in Storybook and the same story rendered by the test runner are styled from the first paint.
5. **A missing sheet fails loudly.** A story run with no compiled sheet is an import error, not a silent unstyled render: the import is a plain static import, never a try/catch or a dynamic import with a fallback.

Gate: none yet. The facts a check would read: from the app's `package.json`, that a `compile-css` script exists and that `prepare` or each script that invokes `vitest` runs it first (parse the JSON and the shell command chain, not a text search); from `git check-ignore`, that the output path is ignored; and from a real-browser story, the computed `font-family` and a token-backed computed `color` of an Astryx `Text` against the theme's resolved values (a story run that sees `serif` and `rgb(0, 0, 0)` fails).
