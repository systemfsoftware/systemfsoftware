---
title: An Astryx app's brand is one defineTheme source built with astryx theme build, its generated files are not committed, and no stylesheet reassigns an Astryx token
applies_when:
  - changing an app's brand colors, fonts, radii or the look of a component
  - adding theme files or CSS custom properties to an app that renders @astryxdesign/core
tags: [design-system, astryx, theme, branding]
---

The brand is one source file that default-exports defineTheme({ name, extends: <base theme>, ... }) and writes only what differs from the base, with per-component overrides under components.

The theme CSS and the built theme object are generated by astryx theme build; roots import the generated output, and the generated CSS, module and declaration files are gitignored.

No hand-written stylesheet assigns a value to a custom property the Astryx theme CSS defines, in :root or anywhere else; a brand change is a change to the theme source.

Decision test: the diff fails if it changes a brand value anywhere other than the theme source, commits a file astryx theme build generates, or assigns a value to an Astryx token (for example --color-accent or --radius-container) in a stylesheet.

Defect it prevents: a token reassigned in a stylesheet makes two sources for one value, so the page and the theme object code reads disagree and the next theme build drops the change; committed generated files drift from the source they were built from.

```css
/* WRONG: global.css */
:root { --color-accent: #0a7cff; }
```

```ts
// RIGHT: theme/brand.ts
export default defineTheme({
  name: 'brand',
  extends: neutralTheme,
  tokens: { '--color-accent': '#0a7cff' },
})
```

Source: @astryxdesign/core Theme docs (build app themes known ahead of time with astryx theme build and import the generated CSS and built theme object; token names start with --); @astryxdesign/core README, Astryx CLI (astryx theme build).
