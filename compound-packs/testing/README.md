# Testing

What a behaviour test specifies and is named for, how its steps and expected values are written, what a test imports, how fakes and adapters are proven, how a failing test or a surviving mutant is resolved, and that configuration gets no test. Work that writes or reviews a test must honor it.

Rules are top-level `.md` files with `title`, `applies_when` and `tags`, cited as `(pack: testing, <file>.md)`. Rule text is evidence that `ce-plan` and `ce-code-review` quote, not an enforcement contract. Subfolders are storage the resolver never reads.
