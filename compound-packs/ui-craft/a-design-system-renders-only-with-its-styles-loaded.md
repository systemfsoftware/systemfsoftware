---
title: A design system's components render only with its stylesheets and theme loaded, and styles compile at build
applies_when:
  - rendering a component library's or design system's components in an app, a Storybook preview or a new entry point
  - adding a styling approach, a CSS-in-JS library or a style build plugin to a web app
  - a component shows the browser's default font, black text or native button chrome instead of the theme
tags: [ui-craft, design-system, css, theme, stylesheet, build, css-in-js]
---

A component from a design system is half a component until its stylesheets and theme provider are loaded: the markup arrives, the styles do not, and the page shows serif text, black-on-white and native buttons. On 2026-10-23 agents' redesigns on a component library came out exactly like that, with zero CSS, and each was reported done. The rule holds for any design system. A repo that enrolls a design system's own pack gets the names of that system's stylesheets, providers and build checks from it.

1. **Load the system's styles wherever its components render.** Every entry that renders the components (the app entry, each extra HTML entry, the Storybook preview, a test harness that renders pixels) imports the system's stylesheets in the order the system documents and wraps the tree in its theme provider. A second entry that forgets them is the usual way an app is styled while its stories are not, or the reverse.
2. **An unstyled render is a defect, proven by computed-style facts, not by eye.** A story (or the screen's capture run) reads, in a real browser, the computed `font-family` of a rendered text component and the computed `color` of a token-backed property, and compares them with the values the active theme resolves: the font family begins with the theme's body family, and the color equals the theme's token resolved on the themed root (read through a probe element so both sides are normalised to `rgb()`). The browser defaults (`Times New Roman` or `serif`, `rgb(0, 0, 0)`) mean the styles did not load. A screenshot judged by eye is not the proof, because a model can describe a plain page as styled.
3. **Styles compile at build.** Author styles with a build-time system: CSS modules, plain CSS files or a utility-class compiler such as Tailwind. No runtime CSS-in-JS (a library that generates and injects `<style>` rules while components render). React's own guidance: "We don't recommend runtime `<style>` tag injection", because it "forces the browser to recalculate the styles a lot more often" and "can be very slow if it happens at the wrong time in the React lifecycle" (react.dev, `useInsertionEffect`). An Emotion maintainer measured a 48% drop in render time (54.3 ms to 27.7 ms over the first 10 renders) after moving a product from runtime CSS-in-JS to Sass modules (Sam Magura, "Why We're Breaking Up with CSS-in-JS", 2022-10-16). Runtime values that change per render belong in a dynamic style the build system supports or in an inline style, never in a runtime stylesheet.
4. **A generated stylesheet that goes missing or lands in the wrong asset fails the build.** When a build step generates CSS (a compiled utility sheet, a theme file), the build checks its output: the sheet exists, and it is in a stylesheet every built document links, not in an async chunk that applies only once some route loads. Dev servers often serve such sheets from middleware, so a misplaced sheet is invisible until production; a build that passes without the sheet is the defect.

Gate: none yet as a shared check. The facts a check reads: in a real-browser story, the computed `font-family` and a token-backed computed `color` of a rendered component against the theme's resolved values (point 2); from the package manager's resolved dependency graph of the app, any runtime CSS-in-JS package in its production dependencies (point 3); from the emitted build directory, the generated stylesheet's presence and whether every built HTML document links the asset that holds it (point 4). Until that check exists, the independent judge of `an-independent-judge-gates-the-merge` receives these facts with the captures and fails a screen whose facts show browser defaults.
